# 08 · 会话交接与续接提示词 v1.0

> **本文档是每个新会话的第一个入口。**
> 它定义「什么时候必须换会话」以及「换会话时交接什么」。

---

## 0. 🔴 硬性原则：一个批次 = 一个会话

**这是硬性原则，不是建议。**

| 规则 | 内容 |
| --- | --- |
| **R-SB-1** | 每完成 `docs/07` §12 的一个批次（P01 / P02 / …），**必须新建对话**，不得在本窗口继续下一批 |
| **R-SB-2** | 新建对话时，用户只需粘贴 §4 的**续接提示词**；不得让新会话重读 `docs/01`–`06` 全文 |
| **R-SB-3** | 批次未通过验收门槛时，**不得进入下一批**，也**不得**开新会话「换个环境再试」 |
| **R-SB-4** | 每个批次收尾时，**必须**更新本文档 §3 状态表与 §4 续接提示词，并提交推送 |

### 为什么

1. **上下文超长会实质性降低质量** —— 长会话中早期约束（架构红线、命名、字段口径）会被稀释，模型开始凭印象作答。
2. **本项目单批产出量已足够大** —— 一个批次通常涉及 5–20 个文件 + 验收测试 + 文档同步，塞进同一窗口会挤压后续批次的可用空间。
3. **交接成本必须低于重读成本** —— 本文档的存在就是为了让「换会话」几乎零成本；否则用户会倾向于硬撑，反而更贵。

### 违反的典型症状（出现即应立刻换会话）

- 开始「凭记忆」写代码，而不是读 `docs/07` 的对应章节；
- 对同一个文件反复小改（说明已经失去整体视图）；
- 忘记了 `registry/` 是 MIDAS API 的唯一真源；
- 回答里开始出现「大概 / 应该是 / 我记得」。

## 1. 交接协议（每个批次收尾必须执行）

```text
① 跑验收门槛 → 留下可复现证据（命令 + 输出摘要）
② 更新本文档 §3 批次状态表（批号 / 状态 / 提交哈希 / 验收证据）
③ 更新本文档 §4「当前续接提示词」→ 换成**下一批**的提示词
④ 更新 docs/07 §15.5「下一步建议」
⑤ 提交并推送
⑥ 输出 §4 的提示词（代码块，用户可直接复制）+ 明确一句话：
   「本批次已完成，本窗口已到边界 —— 请新建对话并粘贴上面的提示词」
```

> ⚠️ **禁止**在未完成 ①–⑤ 的情况下说「下一步做 Pxx」。没有交接的批次不算完成。

## 2. 续接提示词模板（固定骨架）

新会话的提示词必须包含以下 5 块，缺一不可：

```text
【续接会话 · StructAI MCP Server】

■ 工作区与仓库
   G:\MMCP   （remote = github.com/lkxlzx/StructAI-MCP-Server）

■ 本轮唯一任务
   <批次号> <批次名>
   产出文件：<清单>
   验收门槛：<可执行的判定>

■ 开工前必读（只读这些）
   1. docs/08_会话交接与续接提示词_v1.0.md
   2. docs/07_开发方案与任务续接_v1.0.md  §<相关章节> + §12 <批次> + §14 红线
   3. registry/README.md                （仅在涉及 MIDAS API 时）

■ 硬性约束
   - 架构红线：Core 中不得出现任何 MIDAS 内容（grep -R "midas" app/ 预期 0）
   - 技术栈冻结：见 docs/07 §3.1
   - MAPI-Key 绝不写入任何文件（仅环境变量）
   - 涉及 MIDAS API 一律以 registry/ 为准
   - 禁止项：见 docs/07 §14

■ 完成后必须执行（交接协议）
   1. 跑验收门槛并给出证据
   2. 更新 docs/08 §3 状态表 + §4 换成下一批提示词
   3. 提交并推送
   4. 输出「下一批续接提示词」并明确告知：请新建对话
```

