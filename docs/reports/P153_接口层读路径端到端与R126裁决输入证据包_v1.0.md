### 1.3 `PASSED` 行的**接口层实际请求**

```text
[MODEL.QUERY] → GET /gen/OPE/PROJECTSTATUS   200  {"PROJECTSTATUS": {"DATA": […], "DATA_LOAD": […], "HEAD": […]}}
[INFO]        → GET /gen/OPE/PROJECTSTATUS   200  （同一端点；读回条目键 = DATA / DATA_LOAD）
```

`RESULT.ANALYSIS.SUMMARY` 的**零请求**是**判定点**的直接后果：`POST.TABLE` 的
`products = ["CIVIL_DESIGNER", "CIVIL_NX"]`（**不含** `GEN_NX`）⇒ `MidasRegistry.resolve()`
在**发请求前**抛 `STRUCTAI-3000`（`docs/07` §16 R126 的「不臆造、不回落」口径）。

### 1.4 三个**接口层事实**（本批实测，已立 **R127**）

1. **规范化结果的键是 `intent`**：读步骤 = `data["read"]`、取报表 = `data["result"]`
   （**不是** Mock Adapter 的 `data["items"]`）。
   ⚠️ **多端点读 Operation 的聚合键会被覆盖**：`MODEL.LOAD.QUERY` 有 **4** 个读步骤，
   接口层按 `data[step.intent] = …` 落键 ⇒ `data["read"]` **只保留最后一步**（`DB.PRES`）。
   本证据的逐端点读数取自 `steps[]`（**不**依赖该聚合键）。
2. **空块在规范化结果里会退化成一条全 `None` 的条目**：`{"NODE": {}}` 经
   `_items_of({})` → `[(None, {})]` ⇒ Transformer 产出 `{"x": None, "y": None, "z": None}`，
   是**非空 dict** ⇒ 只数「非空条目」会把空块算成 **1** 条（P153 首次实现即踩到）。
   故「空块」判据**只**看**原始块的形态**（`{<read_root>: {}}` 的 `size == 0`），
   读回计数按**有取值**（至少一个字段非 `None`）判。
3. **哨兵的「编号」只认数字键**：单例 / 状态表的读回块是 `{"DATA": …, "HEAD": …}`，
   把键当「既有编号」会让哨兵**假非空**并**中止整批**（P153 首次运行即被中止、零请求）。
   修好后跑前哨兵全空。

### 2.3 **二选一**方案（**只**做输入；方案**只**覆盖字段集缺口的 **4** 个端点）

* **方案 A —— 扩 canonical 字段集**（`docs/04` §20–§31）：逐端点给出要新增的原生字段 +
  `canonical_hint` + 是否 `required`（`A_extend_canonical_field_set.per_endpoint`）。
  需同步 Operation 输入 Schema 与 9 Tool Contract ⇒ **超出**本批授权。
* **方案 B —— 显式允许「按手册示例补原生必填字段」**：逐字段给出**手册示例里的取值**
  （`B_allow_native_defaults.per_endpoint`，取值来源可回溯到
  `registry/live/write_templates.json` 的 `body`）。直接违反既有裁决「**不**臆造字段 /
  **不**虚构 `0`」（`transforms.py` §21 / §26 / §31）⇒ 属**放宽**判定，必须产品**显式**裁决。

⚠️ **两处如实标注**（**不**冒充实测）：
1. **取值缺口不并入二选一**（`value_gaps` 单列）：`DB.ELEM` 的 `MATL` / `SECT` 缺的是
   **前置对象**（材质 / 截面在空项目上建不出来 —— 同一成因），`DB.CONS` 的 `CONSTRAINT`
   差 1 位是 canonical **只**覆盖六自由度（`RW` **明确不臆造**，`transforms.py` §31）。
   本清单**只**登记事实，**不**声称「补上就能通过」。
2. **同一算法的新增发现**（`newly_discovered`）：`DB.BMLD`（缺 `D` · `P` · `USE_ECCEN` ·
   `USE_PROJECTION`）与 `DB.PRES`（缺 `GROUP_NAME`）是**同一算法**在**有 Transformer 的
   模板端点**上扫出来的 —— P152 **未**实测过它们的原生拒绝 ⇒ **只**作为字段差集登记，
   **不**声称会被拒（要断言必须再跑一次接口层 `--probe`）。

### 2.4 实测被拒的 **4** 个端点（逐条留证）

`measured_rejections` 逐条给出 `{endpoint, operation, path, native_status=400,
native_reason=software_api_error, native_error}`：`DB.ELEM` / `DB.MATL` / `DB.CONS` →
`{"error":{"message":"Wrong Field"}}`；`DB.SECT` → `{"error":{"message":"Unknown Error"}}`

## 4. `app/**` 的授权范围与理由（⚠️ 本批要求的**前置声明**）

**授权范围 = 空集。`app/**` 本批一行未改**（`git status --porcelain app` 为空、
`git diff --stat HEAD -- app` 为空；`pyproject.toml` 与 `migrations/` 亦未改 ⇒ **无新依赖**、
**未改表**）。

| 候选改动 | 为什么不改 |
| --- | --- |
| 扩 `transforms.py` 的字段表（`HE_SPEC` / `SECT_BEFORE.*` / `PARAM[0].*` …） | 这些是 **canonical 模型**（`docs/04` §20–§31）的字段集，属**契约**；新增 canonical 字段 = 改契约（且要同步 Operation Schema / 9 Tool Contract）⇒ 超出本批授权；本批**只**把「要扩哪些」做成证据（§2.3 方案 A） |
| 让 Transformer 为缺失字段**补原生默认值** | 直接违反既有裁决「**不**臆造字段、**不**虚构 `0`」⇒ 属**放宽**判定，纪律 4 明令禁止；本批**只**把「默认值会是什么」做成证据（§2.3 方案 B） |
| 让 `MODEL.*.QUERY` 的多端点结果**不覆盖**（`data["read"]` 累积成列表） | 结果按 `intent` 落键是**冻结**的接口层形状（`adapter.execute` 的 `data[step.intent] = …`）；改它属**改契约**。本批的逐端点读数已从 `steps[]` 取，**不**依赖该聚合键（§1.4 事实 1） |
| 把 `read_ids` 的「只认数字键」改成对**所有**键生效 | 已在**工具**（`registry/tools/probe_interface_paths.py`）内修好；`app/` 侧无对应函数（`read_ids` 是探针自己的方法） |
| 把 `POST.TABLE` 的 `products` 补上 `GEN_NX` | 属**数据侧**改动，且**必须**有实测依据（本 build 上该端点是否真的可用**未**实测）⇒ 本批**只**登记（§5 R127(b)） |

⇒ 本批的接口层产出 = **工具 + 证据 + 判定 + 分类账本**，`app/**` **零改动**。
