## 2. 请求体模板：来源可追溯、可逐条复算

P138c 的实测把问题钉死了：`write_probe.derive_body()` 从数据侧 Schema **机械派生**的请求体
（`default` / `const` / `enum[0]` / 类型零值）被实例拒绝（**9 / 10** 个候选 `400 software_api_error`）。
本批把**真实请求体**落成**数据**（**不**硬编码进 Core）：

```text
registry/live/write_templates.json     9 个端点模板 / 31 条 body（9 目标 + 22 前置）
registry/tools/check_write_templates.py  逐条复算（只依赖标准库）
```

**复算规则（可执行、不是声明）**：每条 `body` 必须**等于**
「上游手册 `MIDAS_API_Online_Manual_数据_v1.0.json` 的 `endpoints[].examples[].json` 里
某个 `Assign` 编号下的条目」再**施加本文件声明的 `adjustments`**（逐条 `from` → `to` + `why`）。
`kind = manual_example` **必须**没有 `adjustments`（原样照抄）；`kind = manual_example_adjusted`
**必须**逐条列出改动与理由。**取不到模板就仍如实记 `NO_PAYLOAD_TEMPLATE`**（**不**猜字段、**不**发请求）。

```text
python registry/tools/check_write_templates.py
  -> 端点模板 = 9；校验的 body 数 = 31
  -> 来源 = 手册示例（含调整）的 body 数 = 31
  -> 不可判（无请求 Schema）的 body 数 = 0
  -> ✅ 全部模板的来源可复算；body 无 Schema 未声明的字段；前置链可执行
```

**逐条改动（工具复算 + 人工复核，`adjustments` 全文见数据文件）**：

| 端点 | 模板来源（手册示例） | 改动 | 依据 |
| --- | --- | --- | --- |
| `DB.STLD` | `db/STLD` → Static Load Cases | 无 | 示例即合法载荷工况（`NAME=DL` / `TYPE=D`） |
| `DB.MATL` | `db/MATL` → Standard | 无 | 示例即合法材料（`STEEL` / `EN05(S)` / `S450`） |
| `DB.SECT` | `db/SECT` → Offset : Left-Top | 无 | 示例即合法截面（`DBUSER` / `SHAPE=SB`） |
| `DB.ELEM` | `db/ELEM` → Beam Type | `NODE [30,74] → [1,2]` | 只引用**自建**节点（30 / 74 在本项目不存在） |
| `DB.CONS` | `db/CONS` → Define Supports | `ITEMS[0].GROUP_NAME "Service" → ""` | 示例用了本项目**不存在**的边界组名 → 实例 `400 Unknown Error`（实测）；空串 = 不分组 → `200` |
| `DB.BMLD` | `db/BMLD` → Beam Loads | 无 | 示例即合法（`LCNAME=L` / `CMD=BEAM` / `TYPE=UNILOAD`）；工况与单元由前置链自建 |
| `DB.BODF` | `db/BODF` → Self-Weight | 无 | 示例即合法（`LCNAME=D` / `FV=[0,0,-1]`） |
| `DB.CNLD` | `db/CNLD` → Nodal Loads | 无 | 示例即合法（`ID=1` 指向自建节点、`LCNAME=D`） |
| `DB.PRES` | `db/PRES` → Plate/Plane Stress(Face) : Uniform | `ITEMS[0].LCNAME "Element_Type1" → "D"` | 工况名必须指向**自建**工况；模型须**只含板单元**（实测：有梁单元时 `400` 单元类型不符） |

**另一层校验（测试内，CI 可跑）**：31 条 body 逐条通过**数据侧请求 Schema**
（`jsonschema` 按各 Schema 自身声明的方言，`docs/07` §16 R18）——
`tests/test_midas_write_templates_p139.py::test_p139_every_body_validates_against_the_data_side_request_schema`。

**模板**没有**任何**「改判定」的入口（可执行判定）：
`verification_status_for(availability, enabled)` 的签名里**没有**模板参数；
模板文件里**不得**出现 `availability` / `verification_status` / `products` / `verified_on`；
9 个端点的 `verification_status` 仍逐条等于 `availability` 的机械映射。

## 3. 前置链：只碰自建编号

模板可以声明 `prerequisites`（「目标请求体引用的对象必须先存在」）。探针
（`MidasLiveWriteProbe._create_prerequisite()`）按**声明顺序**创建、目标删除后**逆序**删除：

| 目标端点 | 前置链（自建编号） | 为什么必须 |
| --- | --- | --- |
| `DB.STLD` / `DB.MATL` / `DB.SECT` | （无） | 无引用 |
| `DB.BODF` | `DB.STLD#1`（`NAME=D`） | 按 `LCNAME` 引用荷载工况 |
| `DB.CNLD` | `DB.STLD#1`、`DB.NODE#1` | 条目按 `ID` 引用节点、按 `LCNAME` 引用工况 |
| `DB.CONS` | `DB.NODE#1` | 条目按 `ID` 引用节点 |
| `DB.ELEM` | `DB.MATL#1`、`DB.SECT#1`、`DB.NODE#1`、`DB.NODE#2` | 单元按编号引用材料 / 截面 / 节点；**且节点坐标必须不重合**（实测：全部同坐标 → `400` 几何形状不正确） |
| `DB.BMLD` | `DB.STLD#1`（`NAME=L`）+ 上述 ELEM 的整条链（含 `DB.ELEM#1`） | 梁荷载按 `LCNAME` + 单元号引用 |
| `DB.PRES` | `DB.STLD#1`（`NAME=D`）+ `DB.MATL#1` + `DB.SECT#1` + `DB.NODE#1..4`（矩形四角）+ `DB.ELEM#1`（`PLATE` / `STYPE=2`） | 压力荷载作用于**板**单元，且模型**只**含板单元 |

**纪律与失败归类（可执行判定）**：

- 编号**全部**是本次自建（前置 `item_id` 由数据侧声明，且 `check_write_templates.py` 要求为正整数）；
- 前置创建失败 → 目标如实记 `FAILED`，`detail = prerequisite_failed:<key>#<id>:<原因>`，
  `status_code` 取该次响应的原生状态码，且**零**目标写请求（含**不**发目标清理请求）；
- 无论成功 / 失败，`finally` 里**逆序**清理已建的前置对象（**只**删自建编号）。

## 5. R5：裁决 B + 剩余如实留缺

### 5.1 裁决（**B**）：无请求体 ⇒ **不**建 Schema 文件

| 项 | 值 |
| --- | --- |
| 对象 | `OPE.PROJECTSTATUS` / `OPE.SECTPROP` / `VIEW.SELECT`（`methods` **不含** `POST` / `PUT` / `PATCH`） |
| 裁决 | **B**：**不**新建「只带 `response` 块」的 Schema 文件（`registry/schema/**` 仍 **616** 个） |
| 依据 ① | 这些端点**确实没有请求体** → 请求方向 Schema 是**类别错误**（P138b 已把该项判为「不适用」） |
| 依据 ② | `registry/schema/**` 的定义是**请求体 Schema** 且与 `manifest.json` 带 `schema` 的端点 **1:1**（P08 / P09）；允许「无请求体也建文件」会改变该不变量的**含义**（涉及 616 → 619、加载器 / 导入器 / P08 / P09 断言） |
| 依据 ③ | 收益有限：`verification_status` 由 `availability` 机械映射（`docs/07` §16 R78），与 7 项 AND **不是**同一件事 —— 本裁决**不影响**任何 `verification_status` |
| 后果（如实） | 这 3 个端点的 7 项 AND 的**唯一**缺口 = `response_schema_confirmed` → 如实保持 `PARTIAL`（逐项报出缺哪一项） |
| **恢复条件** | 若将来数据侧**显式**允许「无请求体端点的 response-only Schema 文件」：需同步 `registry/README.md` §2.1 / §3 与 P08 / P09 的「文件数 ↔ manifest 1:1」断言（616 → 619），届时同一判定点即由假转真 |
| 可执行判定 | `tests/test_midas_write_templates_p139.py::test_p139_r5_decision_b_no_response_only_schema_file` |

`DB.LCOM` **不**在这 3 个里：它同样没有请求体，但**连实测解包链都没有**
（其 `read_root` 为空）→ 连 `response` 块都无从生成，故不在任何一侧。

### 5.2 R5 剩余：`POST.TABLE.*` × 3 与 `OPE.BMLD`（**逐条**有数据侧依据）

**① `POST.TABLE.*` × 3** —— 缺的是手册侧 `TABLE_TYPE` 的**机械链接**：

| key | `table_type` | 手册侧证据（可复算） | 结论 |
| --- | --- | --- | --- |
| `POST.TABLE.WEIGHT_IRREGULARITY_X` | `WEIGHT_IRREGULARITY_X` | 手册条目「Weight Irregularity Check - Analysis Story Table」**有** `json_schema`，但 `table_types` **为空** | **无法**机械确认同一操作 → 留缺 |
| `POST.TABLE.CONCURRENT_JOINT_FORCE` | `CONCURRENT_JOINT_FORCE` | 手册条目「Concurrent Joint Force Table」**有** `json_schema`，但 `table_types` **为空** | 同上 |
| `POST.TABLE.STORY_SHEAR_FORCE_COEFFICIENT` | `STORY_SHEAR_FORCE_COEFFICIENT` | 手册里近名条目声明的是**别的** token（`table_types = ["STORY_SHEAR_FOR_RS"]`）且**没有** `json_schema` | 同上 |

**恢复条件**：手册侧为这些条目补 `table_types`（或在官方文档里明确 `TABLE_TYPE` ↔ 条目的一一对应）
→ 生成链即可机械映射出请求 Schema。**本批不臆造、不按标题猜**。

**② `OPE.BMLD`** —— 缺的是「是否与 `/DB/BMLD` 同一操作」的官方确认：

| 事实 | 值 | 来源 |
| --- | --- | --- |
| 手册条目 | **只有** `db/BMLD`；**没有** `ope/BMLD` | 上游手册 `endpoints[].input_uri` |
| 数据侧声明 | `uri = /OPE/BMLD`、`methods = (POST,)`、`products = (CIVIL_NX,)`、无 Schema 文件、无 `read_root` | `registry/manifest.json` |
| 对照 | `DB.BMLD`：`uri = /DB/BMLD`、`methods = (POST, GET, PUT, DELETE)`、有 Schema 文件、`read_root = BMLD` | 同上 |
| **本批只读实测**（gen-local，零副作用 `GET`） | `/OPE/BMLD` → **`405`**（路由存在、**只允许 `POST`**）；`/OPE/LINEBMLD` → **`405`**；对照 `/DB/BMLD` → **`200`** | 本机 GEN NX 实例 |
| 结论 | 两条路由的**方法集不同**（`405` vs `200`）⇒ **不能**视为同一操作、**不能**把 `db/BMLD` 的 Schema 挪给 `OPE.BMLD` → 如实留缺 | 实测 |

**恢复条件**：官方确认 `/OPE/BMLD` 与 `/db/BMLD` 的语义关系（或手册补 `ope/BMLD` 条目与 `json_schema`）。
⚠️ 该只读实测**不**在 CI 里复跑（需真实实例）；CI 侧固定的是**数据侧**事实
（`tests/test_midas_write_templates_p139.py::test_p139_r5_remaining_gaps_are_backed_by_data_side_facts`）。

## 6. 状态码保真度（P135 的「小保真度」缺口）
