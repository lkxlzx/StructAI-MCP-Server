## 1. 为什么用参数化

前两轮（钢柱、单根简支梁）是**手搓单点模型**，一次只能测一个、发现一个问题要重跑一遍真机 —— 慢且易漏。
本轮改成**参数化**：模型骨架固定（简支梁：3 节点 2 单元，左铰右滚，Q355 + GB50017-03 中国规范同族），
只把 **跨度 / 跨中集中力** 抽成用例表，**批量套模板跑**，一屏看出参数变化下的差异。

## 3. 参数化一眼看出的东西（价值所在)

1. **物理正确性在所有参数下成立**：真机跨中弯矩 My 与手算 `PL/4` 在**全部 4 个用例**都稳定差 ~10%（6m:247.5/225、8m:440/400、10m:687.5/625、12m:990/900）—— 一致偏差可归因于**构件自重**，证明分析引擎在不同跨度/荷载下**都算对**。
2. **挠度对跨度的高次敏感一眼可辨**：uz 从 6m 的 −0.044 → 12m 的 −0.649（跨度翻倍、挠度 ~15 倍），符合受弯挠度随 L 快速增长。
3. **设计全 NG**：占位截面 `P154S1` 截面模量过小，所有用例弯矩需求都远超其承载力 —— 规律一致，问题定位明确（不是参数特例，是截面通病）。

> 这正是参数化测试的目的：**不是"再跑一个模型确认能跑通"，而是"一次扫一批，看出规律、定位系统性问题"**。

## 4. 参数化机制（可复用）

- **用例表** `BEAM_MATRIX`（`probe_beam_chain_p189.py` 顶部）：每项 `{case, span, mid_fz}`，加一行即加一个模型。
- **骨架参数化** `_beam_steps_via(..., span, mid_fz, project_path)`：同一套 16 步模板，套不同数据。
- **批量入口** `--matrix`：遍历用例表，每用例独立 stack（临时库 + 专用实例 + 独立 `.tmp_p189/<case>.mgbx`），汇总矩阵到 `registry/live/beam_matrix_probe_p189.json`。
- **单模型** `--probe [--span X --mid-fz Y]`：跑单个，可命令行覆盖参数。

```bash
# 批量跑矩阵（一条命令 4 个模型）
python registry/tools/_run_with_env.py gen registry/tools/probe_beam_chain_p189.py --matrix
# 单模型 + 覆盖参数
python registry/tools/_run_with_env.py gen registry/tools/probe_beam_chain_p189.py --probe --span 7 --mid-fz -180000
```

1. **参数化矩阵 4/4 全 PASSED**，零残留，中国规范同族，SAVE_AS 带路径无弹窗。
