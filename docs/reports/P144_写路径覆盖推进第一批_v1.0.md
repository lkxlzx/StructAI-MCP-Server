## 1. 新裁决 **R100**：候选判据 + 「能建必须能删」

| 项 | 内容 |
| --- | --- |
| 原判据（P138c） | 候选 = 「有写方法 ∧ 有读路径 ∧ **Transformer 已注册** ∧ 非危险形态 ∧ 产品可得」 |
| 问题 | 探针**只**用 Transformer 的 `wrapper_key()`（请求体来自数据侧模板或 Schema 机械派生）—— 把「是否已注册 Transformer」当门槛，等于要求**每个**端点都在 Core 里写一份 canonical↔native 映射，而那是**adapter 执行**才需要的东西，**不是**验证端点的前提 |
| **新判据（R100）** | 候选 = 「有写方法 ∧ 有读路径（`GET` + `read_root`）∧ **（Transformer 已注册 ∨ 有数据侧模板）** ∧ **有 `DELETE`** ∧ 非危险形态 ∧ 产品可得」 |
| 包装键来源 | Transformer 已注册 → 用它的 `wrapper_key()`；否则取**数据侧** `registry` 的 `wrapper.write`（`Assign` / `none`）—— **不**臆造、**不**硬编码 |
| 「能建必须能删」 | 该产品没有 `DELETE` 的端点**不**入候选：三步链会「建了删不掉」，在真实项目里**留下残留**（P144 之前无此护栏，只是因为既有 11 个候选恰好都有 `DELETE`） |
| 新原因词 | `probe_key()` 把「该产品没有写方法」与「Transformer 未注册」**分开记因**：`no_write_method_for_product` / `no_transformer_for_endpoint`（都 `NO_PAYLOAD_TEMPLATE` + **零**写请求） |
| 不改什么 | **不**改 9 Tool Contract；**不**改 `verification_status` 的判定；分母仍 **609**；模板仍**只**在 `registry/**` |

**可执行判定** = `tests/test_midas_write_coverage_p144.py`（6 项）+ `tests/test_midas_write_coverage_p142.py`
（候选集 18/17/0、`eligible ⊆ candidates`、模板可入候选）+ `tests/test_midas_registry_p138.py`
（候选不变量改为「Transformer **或** 模板」+ `DELETE`）。

## 3. 新裁决 **R101**：3 个端点**如实留缺**（不是「没测」）

| 端点 | 实测证据 | 为什么数据侧无法表达 | 处置 |
| --- | --- | --- | --- |
| `DB.ACTL` | `GET /info/db/ACTL` 自省字段 = `[ARDC, ANRC, CSECF, TRS, BMSTRESS, CRBAR, ITER, TOL, **ACWC**]`；手册示例用 `CLATS`；`POST` → **400 `Wrong Field`** | 模板的 `adjustments` **只**能改**值**、**不能**改名 → 无法把手册的 `CLATS` 变成 build 的 `ACWC` | **留缺**；恢复条件 = 上游手册 / 新 build 的字段集与本 build 一致 |
| `DB.CLWP` | 自省字段与本例**完全一致**（14 个）；`POST`（`Assign` 与 `Argument` 两种包装都试）→ **400 `Wrong Field`** | 字段名一致却拒绝 ⇒ 原因不在字段名，数据侧**无法**从证据推出 | **留缺**；恢复条件 = 官方手册给出可接受示例 |
| `DB.EDMP` | `POST` → **200** 但 `GET` 读不回（`{"EDMP":{}}`） | 该表按**构件号**取值 —— 空项目没有构件，属**非零前置** | 归下一批（需先建节点 / 单元的前置链） |

> ⚠️ 三个端点**没有**模板 ⇒ **不**入候选 ⇒ 不会污染 `limit`、不会产生假的 `FAILED` 记录。
> 本批**没有**放宽任何判定：`PASSED` 仍要求「创建 → 读回 → 按路径 key 删除」三步全成立。
