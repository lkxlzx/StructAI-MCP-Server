# P186 项 B —— `DESIGN.RC.KDS-41-20-2022.REBC` 的 `400` 真机归因排查

> 批次：**P186-B**（真机写实验，**用户已显式授权**；`gen-local` 空项目）
> 目的：验证 `docs/08 §4` P186-B 的**未排除假设**「`400` 是否因**前置对象缺失**（单元 / 截面）」。
> 红线：**阳性对照先行**（R157）· **判据 = 效果 + 原生文案**（铁律 ⓪）· **零残留** · **不碰** `*-ANAL`（R154）。
> 证据：`registry/live/rebc_prereq_probe_p186.json`。

---

## 1. 结论（一句话）

**REBC 的 `400` 不是「前置对象缺失」，而是「请求体形状 / 键名层」问题**（`{"error":{"message":"Wrong Field"}}`）；
即使**前置单元真实存在**（阳性对照已建成并读回），`PUT REBC` 仍回 **`400 Wrong Field`**。
⇒ 与 P169 的 `POST.TEXT`（`TABLE_TYPE`→`TEXT_TYPE`）**同族**：`Wrong Field` = **键名 / 顶层形状**不对，**不是**「缺单元 / 缺截面」。

## 2. 实测事实（原生文案为准）

| # | 步骤 | 方法 | 原生结果 |
|---|---|---|---|
| 0 | 基线：空项目 | `GET /db/NODE` `/db/ELEM` | `200 {"message":""}`（空） |
| 1 | **阳性对照**：建节点 1/2 | `POST /db/NODE` ×2 | **`201`** + 读回**真值** |
| 2 | 阳性对照：建单元 1（引用节点 1→2） | `POST /db/ELEM` | **`201`** + 读回 `NODE:[1,2,0,…]`（**真落库**） |
| 3 | **目标：`PUT REBC`（单元 1 已存在）** | `PUT /DESIGN/RC/KDS-41-20-2022/REBC` | **`400 {"error":{"message":"Wrong Field"}}`** |
| 4 | 变体：`CREATE_SUB_SECTION=true` | 同上 | **`400 Wrong Field`**（同形） |
| 5 | 读回 | `GET /DESIGN/RC/KDS-41-20-2022/REBC` | `200 {"REBC":{}}`（**未落库**） |
| 6 | 清理（逆序删单元→节点2→节点1） | `DELETE` ×3 | `200` |
| 7 | **零残留核对** | `GET /db/NODE` `/db/ELEM` | `200 {"message":""}` ⇒ **空** ✅ |

### 关键对照（归因的决定性差异）

- **前置缺失型错误**（例：`POST /db/SECT` 尺寸不对）⇒ 原生 **中文**「**截面尺寸输入有错误。**」——这是**取值 / 形状**级、且**指名**缺什么。
- **REBC** ⇒ 原生 **英文**「**Wrong Field**」——这是**键名 / 顶层字段**级（本 build 在 `Wrong Field` 上的**同族唯一已知成因**是键名错，见 `E-02`：`POST.TEXT` 的 `TABLE_TYPE` 任何取值都 `Wrong Field`，实测契约键是 `TEXT_TYPE`）。
- ⇒ **有单元 / 无单元，REBC 都回 `Wrong Field`** ⇒ **前置对象与 `400` 无关**（这是本批要证伪的假设，已证伪）。

## 3. 为什么不能「调到跑通」

- **手册无权威示例**：`DESIGN.RC.KDS-41-20-2022.REBC` 的 `source = repo_midas_api`（GitHub 韩文整理版，**非** Gen NX 帮助中心）。
  `MIDAS_API_Online_Manual_数据_v1.0.json`（Gen NX 手册）里 **`REBC` 出现 0 次** ⇒ **无第二来源**可复算「正确的 `Assign` / `ITEMS` 键名或顶层形状」。
- **红线 ⑥「不发明」**：在无权威示例、且真机只回 `Wrong Field`（不指名缺哪个键）的情况下，硬凑请求体形状 = 发明取值 ⇒ **违反** `R151` 的方法学（宁可如实留缺，也不硬凑）。
- ⇒ 因此本项**不**继续调到「能跑通」；正确出口是**向 MIDAS 侧确认 REBC 的请求体契约**（键名 / 顶层包装 / ITEMS 必填），与 P186-A 问题④ `OPE.LCOM-GEN::DGNCODE`（`Wrong Field` / 键名）**同族**。

## 4. 附带确认（正面结果）

- **写路径 / 读回 / 清理仪器可靠**：`POST /db/NODE`、`POST /db/ELEM` 均 `201` + `GET` 读回真值；
  `DELETE` 后 `GET` 回空 ⇒ **阳性对照成立（R157）**，本批结论可信。
- **零残留**：实验在 `gen-local` 空项目上进行，结束后 `GET /db/NODE` / `GET /db/ELEM` 均 `{"message":""}`。
- **未碰崩溃族**：`REBC/REBR` 的 `requires_analysis=false`，全程**未**发任何 `*-ANAL`（`R154`）。
