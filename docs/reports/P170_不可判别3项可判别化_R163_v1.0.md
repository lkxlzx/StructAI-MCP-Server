## 0. 一句话结论

P169 判为「**不可判别**」的 **3** 个 `PARTS` 端点（本模型无该表数据 ⇒ 基线就是**空块**），
本批**建了一个带相应结果的自建模型** ⇒ 重跑**同一份**探针（**判据已就位**）⇒ **6 / 6** 个端点**可判别**
⇒ **收口 11 → 14** · **留缺 7 → 3**（余 **3** 项**全部**是**产品 / 数据侧**澄清）。

> **最大的产出不是「又收口 3 项」，而是 P169 的「需要什么」写错了一处**：
> P169 写 `RESULTANT_FORCES`「需**板 / 实体**单元」—— **不准确**。
> 手册 `db/VSEC`（虚拟截面）+ `db/VBEM`（虚拟梁）表明该表由**虚拟梁**驱动
> ⇒ 缺的是**虚拟截面定义**，**不是**板单元。本批**两样都建**（板网格 + 虚拟截面）以**一次**消除两个疑点。

## 2. 顺带实测的**三条**原生事实（勘误 **§1.6c**）

### 2.1 **E-04**：`db/ELEM` 的 `STYPE: 0` 对 `PLATE` **非法**

隔离探针（**单发**，逐变体读回）实测：

| 体 | 原生 | 建出？ |
| --- | --- | --- |
| `TYPE: "PLATE"` + `NODE` 8 项 + **`STYPE: 0`** | `400 发现错误，将数据 单元 输入给了单元号 N` | ❌（**整批回滚**） |
| `TYPE: "PLATE"` + `NODE` 8 项 + `STYPE: 1` | `400 不能添加/编辑单元。单元 N 的几何形状不正确。` | ❌（**几何**错，见下） |
| `TYPE: "PLATE"` + **正确四边形** + `NODE` 8 项（**无** `STYPE`） | `201` | ✅ |
| `TYPE: "PLATE"` + 正确四边形 + `NODE` **4** 项 | `201` | ✅ |
| `TYPE: "BEAM"` + `STYPE: 0` | `201` | ✅（**梁**正常） |

⚠️ 表里第 **2** 行揭示**另一条**：`STYPE: 1` 让原生改报**几何**错 —— 即 `STYPE` 的取值**会改变
原生对同一组节点的解释**（本批**只**记录，**不**深挖）。
⇒ **本批结论**：`PLATE` 的请求**不**带 `STYPE`（`additionalProperties` 不拦未声明字段 ⇒ **不**收紧闸门）。

### 2.2 **E-05**：`DESIGN.STEEL.…TABLE` 的 `PARTS.default = ['All']` 实测**空块**

`All` 是**该端点 Schema 的 `PARTS.default`**（= 手册声明的「全部部位」），实测与**伪**取值 `PartZ`
**同形**（空块）⇒ **声明的 `default` 错**。⚠️ 与 **E-02** **同族但结论相反**：
`E-02` 是「**声明错、示例体对**」，`E-05` 是「**声明自己的 `default` 错**」。
⇒ 本批**不**收口 `All`、**也****不**删它（**只增不减**），登记待**产品侧**澄清。

### 2.3 **E-06**：`DESIGN.STEEL.DSTL` 的 `PUT` ⇒ `400 Wrong Field`（**已知**）

`docs/nxsdk_review/evidence/02_实测发现_中文摘要.md` 记 Civil 上同样如此；Gen NX 亦同。
⚠️ **不**阻塞设计链 —— `DCO` 的体**自带** `DGNCODE` ⇒ 设计**真的**跑出结果
（`STEELMEMBERDESIGNFORCES` **5** 行）。本批**如实记录**，**不**改 `app/**`。

## 3. 修掉的一个**判据 v2 的漏洞**（**R151 的镜像**）

`registry/tools/sync_parts_enum.py` 原先的规则是「端点**可判别** ⇒ 来源①（手册示例体）**全量**入枚举」。
本批**实测**发现该规则会**误收**：`DESIGN.STEEL.…TABLE` 的示例体取值是 **`All`**，
而 `All` **实测无效**（空块）⇒ 原规则会把**实测无效**的取值写进枚举 = **按示例体硬凑**
（正是 **R151** 要防的，只是**方向相反**：R151 防「示例体太窄」，本条防「示例体**错**」）。

**修正**：可判别时来源①必须与**实测有效**取**交集**。⚠️ 修正后**零差异**（`All` 当时**未**落盘）。

## 8. 本批的教训

1. **「需要什么」也是判据的一部分 —— 它也会错。** P169 写 `RESULTANT_FORCES`「需**板 / 实体**单元」，
   而手册 `db/VSEC` + `db/VBEM` 表明缺的是**虚拟截面定义**。⚠️ 若本批**照 P169 的说法**只建板，
   就会**仍然拿不到**结论（板建了但**没有虚拟截面** ⇒ 该表仍空）⇒ 会**误判**成「建了板也不行」。
   **教训**：留缺说明里的「恢复条件」要**回到手册**核对，**不**照抄上一批的措辞。
2. **「可判别化」要一次消除**所有**疑点。** 本批**两样都建**（板网格 + 虚拟截面）——
   这样无论该表由**哪样**驱动，都能拿到结论；否则要**两轮**真机测量。
3. **同一个探针在不同模型上会得到不同结论 —— 证据要按模型分开存。**
   `PARTS` 的「有效取值」**随模型**变（`BEAMFORCE` 的 `Part1/4` 在两模型上都有效，
   而 `THISBEAMFORCE` 的 `Part1/4` 在两模型上都**空块**）⇒ 本批**不覆盖** P169 的证据，
   改为**合并**两份。⚠️ 这是**工程纪律**：`--evidence` 参数让「重跑」**不**破坏**既有**证据。
4. **「示例体对」不是普适真理。** P169 的 **E-02** 结论是「**声明错、示例体对**」；
   本批的 **E-05** 发现 `DESIGN.STEEL.…TABLE` 的 `PARTS.default`（**声明**）**也**错
   ⇒ **声明的每一个取值都要实测**（`default` 也一样）。
5. **修漏洞要顺手 —— 但**零差异**才是好信号。** 本批修了生成器「可判别 ⇒ 示例体全量入枚举」的漏洞；
   修正后**零差异**（`All` 当时**未**落盘）⇒ 说明**收口结果未变**、只是**规则**变严了。
   ⚠️ 若修正后**有**差异，那说明**旧规则已经写错**了枚举 ⇒ 必须**单独**裁决。
