### 2.3 **R131**（新）：`BUILD.COLUMN` 的**材质**子步**结构上**发不出可被接受的 body

- **实测**：`POST /DB/MATL` 的 body **只**有 `NAME` / `TYPE` / `PARAM[ELAST, POISN, DEN]` ⇒ 原生 `400 Wrong Field`；
  **节点 / 单元都已建成**（再读确认）⇒ **不**是端点不存在、**不**是形状（外层键 = **编号**）、
  **不**是探针参数缺失。
- **离线可复算**：`adapter._column_payloads` 只填 `name` / `type` / `elastic_modulus` / `poisson_ratio` /
  `density`（**A′ 的 11 个原生字段一个都不在**）；而**同一端点**在 `MODEL.MATERIAL.ASSIGN` 下、
  **补齐 A′ 的 11 个字段**后**实测可用**（P154 / P157 写路径的 `DB.MATL` 行 `200`）。
- **结论**：**`docs/07` §13.5 的参数集不足以在 GEN NX 上建材质** —— 这是旗舰链的**第一处结构成因**。
- **未修**（属 `app/**` 的 `_column_payloads` + 契约侧的 canonical 字段集，**未**获授权）。
  恢复条件 = 显式授权（扩 `BUILD.COLUMN` 的材质载荷 / 或让 §13.5 的参数集带上 A′ 的字段），
  **须**同时复核 `DB.SECT` 的 **6** 个 A′ 字段。

### 2.4 **R132**（新）：接口层**没有**任何 Operation 能**创建**工况（`DB.STLD`）

- **实测**：`POST /DB/CNLD` → `400 Not Found Key`，而**节点 2 存在**（同批的 `DB.NODE` 再读 = `["1","2"]`）
  ⇒ 缺的是**工况**（`LCNAME = "AXIAL"`）。**读**：`GET /DB/STLD` → `{"STLD": {}}`（空）。
- **离线可复算**：`MODEL.LOAD.ASSIGN` 的编排**声明**了 `DB.STLD` 的 `write_load_case` 步，但
  `select_steps` 对**每一种**已映射荷载类型（`NODE_FORCE` / `NODE_MOMENT` / `BEAM_FORCE` / `BEAM_MOMENT` /
  `PRESSURE` / `SELF_WEIGHT` / `FLOOR_LOAD`）**都只**返回该类型对应的那一步 ⇒ `DB.STLD` **永不**被执行；
  而 `MODEL.LOAD.DELETE` **能删** `DB.STLD`（**不对称**）；**全库范围**没有第二个 `write_load_case` 端点。
- **结论**：`MODEL.LOAD.ASSIGN` **结构上**无法在**没有工况**的项目上成功 —— 这是旗舰链的**第二处结构成因**。
- **未修**（属 `app/**` 的编排 / `select_steps`，**未**获授权）。恢复条件 = 显式授权（让
  `MODEL.LOAD.ASSIGN` 先执行 `DB.STLD` 的创建步，**或**新增一个能创建工况的 Operation ——
  后者**属改 9 Tool Contract**，须**单独裁决**）。

## 3. **R130**（新，本批发现）：`ITEMS` 形态端点的**读回**退化

`MidasAdapter._read` 用 `_items_of(read_root 块)` 解包；对编号键映射
`{"1": {"ITEMS": [<叶子>]}}` 它返回 `("1", {"ITEMS": [<叶子>]})` —— 即**包装体**，**不是**叶子 ⇒
`BoundaryTransformer.from_native` 拿不到 `ID` / `GROUP_NAME` / `CONSTRAINT` ⇒ **7 个自由度全 `None`**
（只有由**编号键**补的 `id` 有值）。

**实测**（写路径证据的 `readback.observed`）：

```text
DB.CONS  add  → {"present": true, "observed": {"id": "1", "node_id": null, "group_name": null,
                                               "ux": null, "uy": null, "uz": null,
                                               "rx": null, "ry": null, "rz": null, "rw": null}}
DB.NODE  add  → {"present": true, "observed": {"id": "1", "x": 1.0, "y": 2.0, "z": 3.0}}     ← 对照：有值
DB.MATL  add  → {"present": true, "observed": {… 全部有值 …}}                                ← 对照：有值
```

**离线可复算**：`_items_of({"1": {"ITEMS": [<叶子>]}})` == `[("1", {"ITEMS": [<叶子>]})]`。

- **影响面** = **4** 个 `ITEMS` 形态端点（`DB.CONS` · `DB.CNLD` · `DB.BMLD` · `DB.PRES`）。
- ⚠️ **不**影响写路径**判定**（判定 = 「该编号**在**读回里」，键来自编号、**不**依赖叶子字段），
  但**限制**其**证明力**：`DB.CONS` 的 `PASSED` 证明的是「**建成且可按编号读回**」，
  **不**是「canonical 取值可回读」。
- **未修**（属 `app/**` 的 `_read` / `_items_of`，**未**获授权）。
- ⚠️ P153 的读路径证据在**空项目**上测得 `empty_block` ⇒ 该退化**当时不可见**（本批因写路径的
  **非空**读回才暴露）。

## 8. 本批的**教训**（写给下一批）

1. **「前置未满足就不硬跑」是对的，但「前置」要先问清楚**：本轮原以为旗舰链要等 **D4 的第二个项目**，
   用户澄清「MIDAS 自身可建模分析，第二个项目只作扩展」⇒ 立刻可跑。**澄清一次**比**猜一整个批次**便宜。
2. **数据侧的一个字段改动会**连锁**到多个钉住计数**：`products` 补一个产品 ⇒
   写路径分母 +1 · 读路径成因前移 · 取报表目标集 +1 · blocked +1。**改数据前先跑全部 `--check`**，
   否则会在收尾时才发现 11 个测试要同步。
3. **A/B 必须只改一个变量**（P156 的教训）在本批**再次**应验：旗舰链的**阶段 A 与阶段 B**
   把「规格链失败」与「②–⑤ 的未知面」**分开**记录，才看清「① 是材质字段集、② 是工况缺失」
   是**两个独立**成因 —— 若只跑阶段 A，会误判为「旗舰链整体不可用」。
4. **`2xx` 不等于成功**（R128）：② 的判据**必须**以**再读**为准；本批的 `readback.observed` 全 `None`
   也**不**影响判定（键在 = 在），但**暴露**了 **R130** —— **判据的**证明力**也要如实写清**。
