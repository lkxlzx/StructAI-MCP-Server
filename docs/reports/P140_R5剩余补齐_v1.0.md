## 3. 生成链（**不**手抄、**不**臆造）

新增数据侧工具 `registry/tools/sync_request_schemas.py`（**只依赖标准库**；默认**预演**、
`--write` 写回、`--check` 断言「已落盘 == 机械结果」）：

| 来源种类 | 判据（工具**逐条断言**，取不到即报错退出） |
| --- | --- |
| `manual_json_schema` | 手册 `endpoints[].json_schema` 里 `TABLE_TYPE.enum` **包含**该端点 token（**恰好一条**条目） |
| `manual_spec_table` | 手册条目**没有** `json_schema`、标题命中声明的表名、且有完整规格表 |

**规格表 → JSON Schema 的机械规则**（全部取自表格本身，见工具模块文档）：
字段行 = 6 列且第 3 列是 `"<NAME>"` 引号键；行号带 `(n)` / `n.m` 的行写进**上一个顶层字段**的
`properties`；`String/Integer/Number/Boolean/Object/Array [X]` → 小写 JSON Schema 类型
（未给类型 → **不写** `type`）；规格表自己声明 `"Argument"` 行 → 用它当包装键；
`TABLE_TYPE` 若记的是**兄弟 token**，替换为本端点 token 并在 `description` 里**注明依据**。

## 4. 真实实测：`/POST/TABLE` 的 token 判别（含对照）

**步骤**（**只**碰自建 ID；前后各核对一次哨兵）：

```text
① 只读核对：DB.NODE / DB.ELEM / DB.MATL / DB.SECT 既有编号 = 0（空白项目）
```

## 5. `OPE.BMLD` 的结案：**不是**同一操作

| 事实 | 值 | 来源 |
| --- | --- | --- |
| 语义 | `/OPE/BMLD` = **Beam Detail Analysis（梁详细分析）**；`/DB/BMLD` = **Beam Loads（梁单元荷载）** | 开发文档 §5 与 `registry/products/*/…BMLD.yaml` 的 `title` |
| 方法集 | `(POST,)` vs `(POST, GET, PUT, DELETE)` | `registry/manifest.json` |
| 产品 | `(CIVIL_NX,)` vs `(CIVIL_NX, GEN_NX)` | 同上 |
| 手册条目 | **没有** `ope/BMLD`（只有 `db/BMLD`） | 上游手册 `endpoints[].input_uri` |
| 只读实测（P139，gen-local，零副作用 `GET`） | `/OPE/BMLD` → **`405`**（只允许 `POST`）；`/DB/BMLD` → **`200`** | 本机 GEN NX |
| 请求 Schema | 开发文档**已给出**完整 JSON Schema（`required: [Argument]` → `LOAD_CASE_COMB` / `ELEMENT` / `STRESS_TYPE`） | `MIDAS_API_开发文档_v1.0.md` |

→ R5 的 `uri_differs_in_manual` 类**结案**：**不是**同一操作，且其 Schema **另有**（可追溯的）来源。
