## 3. P136b —— response 方向 Schema（R87 / R90）

**生成器**：`registry/tools/sync_response_schemas.py`（只依赖标准库；默认预演，`--write` 写回）。

**「已实测」判定**（**不**臆造）：`availability == verified`（`registry/README.md` §4：
至少一个实例 GET 成功）**且** `methods` 含 `GET` **且**该端点有可读的 Schema 文件
**且**声明了解包链（`wrapper.read_root` 或 `wrapper.read_root_path`）。

| 项 | 数量 |
| --- | --- |
| 已实测端点（`verified` + `GET`） | **245** |
| 补了 `response` 块的端点 | **239** |
| 跳过（无 Schema 文件） | **6** —— `DB.LCOM` / `OPE.PROJECTSTATUS` / `OPE.SECTPROP` / `OPE.STORY_IRR_PARAM` / `OPE.STORY_PARAM` / `VIEW.SELECT` |
| 跳过（未声明解包链） | **0** |

**写入形态**：在**同一份** Schema 文件里**追加** `response` 块（**不**新增文件，
故 `registry/schema/**` 仍是 **616** 个文件、P09 的「无孤儿 / 无缺文件」不变；
请求方向的 `schema` **一行未改**）：

```json
"response": {
  "direction": "response",
  "source": "l4_measured_envelope",
  "schema": {"$schema": "…draft/2020-12/schema", "type": "object", …}
}
```

**只按实测写**（载荷字段一个都不写）：

| 情形 | 分支 |
| --- | --- |
| NX 系（`{<read_root>: {...}}`，`registry/README.md` §4 实测口径） | `{"required": [<read_root>], "properties": {<read_root>: {"type": "object"}}}` |
| 声明了解包链（`CIVIL_DESIGNER` 实测在 `result.return_value`，R83） | 按链逐层 `required` / `properties`，**叶子类型留空**（`{}`，未实测 → 不猜） |
| 两种产品信封不同（如 `DB.NODE`） | `oneOf` 列出两个分支 |

**幂等**：第二次运行输出「补 response Schema 的端点 = **0**」。

**判定点（同一处）**：`live.py` 的 `seven_and_verdict` / `registry_evidence` ——
「Response Schema 已确认」由 `registry.response_schema_document()` 如实判定
（P136 之前该项**恒为假**，R87）：

| 类别 | 数量 | 7 项 AND 结论 |
| --- | --- | --- |
| 有 `response` 块且其余 6 项成立 | **238** | `VERIFIED` |
| 有 `response` 块但请求 Schema 是**非法 JSON 字符串**（`DB.MBTP`，R19） | **1** | `PARTIAL`，缺 `request_schema_confirmed`（**不**补、**不**猜） |
| 未实测 / 无 Schema 的端点 | 其余 | `PARTIAL`，缺项里**恒**含 `response_schema_confirmed` |

**R90（ETABS）不变**：无 ETABS 安装 / 专用凭据 / 项目 / 测试模型 → 无 response 方向 Schema → **不升**。

## 4. 真实实例只读复核（L4，零副作用）

对三个实例的全部只读端点做 `GET` 探测（顺序执行，云端中继超时最多重试 3 次）：

| 实例 | 只读端点 | `PASSED` | `PARTIAL` | `FAILED` |
| --- | --- | --- | --- | --- |
| GEN NX（本机） | 243（数据侧摘除 14 条后） | **220** | 1 | **22** |
| CIVIL NX（云端） | 211（数据侧摘除 5 条后） | **45** | 164 | **2** |
| Civil Designer（云端） | 14 | **13** | 1 | 0 |
| **合计** | **468** | **278** | **166** | **24** |

**与 P134 报告 §3 逐条对齐**（把本批摘除的 14 + 5 条按实测补回）：

| 实例 | P134 §3（`PASSED` / `PARTIAL` / `FAILED`） | P136 复核换算 |
| --- | --- | --- |
| GEN NX | 220 / 1 / 36 | 220 / 1 / `22 + 14 = 36` ✔ |
| CIVIL NX | 45 / 164 / 7 | 45 / 164 / `2 + 5 = 7` ✔ |
| Civil Designer | 13 / 1 / 0 | 13 / 1 / 0 ✔ |
| **合计** | **278 / 166 / 43** | **278 / 166 / 43** ✔ |

**原始 URI 复核**（绕过 registry 的产品过滤，逐条确认「解析期拒绝」有实测依据）：

| 组 | 条数 | 结果 |
| --- | --- | --- |
| GEN NX 组（含 `DB.SPAN`） | **15** | 全部 `404` |
| CIVIL NX 组 | **7** | 全部 `404`（响应顶层键 `error`） |

**§4.1 的计数复算（P136c）**：GEN NX 的 **36** 条 `FAILED` = **21** 条 `-M1` 变体
（本次复核逐条命中：`DB.ACTL-M1` … `DB.THOO-M1`）+ **15** 条桥梁 / 铁路专项表
（14 条 + `DB.SPAN`，由原始 URI 复核确认 `404`）。原文写作「25 条 + 其余 11 条」
（合计 40 ≠ 36）系计数瑕疵，已按清单更正，并与 `instances.yaml` 的 gen-local 备注
