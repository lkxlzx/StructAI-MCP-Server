> 批次：**P159** ｜ 状态：✅ **已验收** ｜ 授权范围：`app/**` = **6** 个文件 + **契约**（Operation 70 → 71、能力码词表 41 → 42）
> 前置：P158（R130 读回退化闭环 + R139 `DOC.NEW` 实测收口）
> **用户口径（本批的架构判据）**：
> **单位是"输入"，不是常量。** UI 新建模型时选、AI 建模/提示词阶段**先定口径**，
> **不**在核心里写死；核心只负责**承载**它，并让**后续所有步骤**在该口径下执行。

## 1. 问题（R133 的重新定义）

### 1.1 现状核实（P159 开工前）

```text
① 核心里**完全没有**"单位"这个概念（app/** 搜 unit 只命中 UnitOfWork，与单位无关）
② DB.UNIT 是 verified 端点（GET, PUT，字段 FORCE / DIST / HEAT / TEMPER）
   但**没有任何 Operation 引用它**   ← 与 R136（荷载组合）、R139（DOC.NEW）同族的契约缺口
```

⇒ 契约里**没有地方**能"先定单位" ⇒ UI 与 AI 都无处下手；而"把单位写死进核心"**方向就是错的**。

### 1.2 正确的架构口径（用户给定）

| 层 | 职责 |
| --- | --- |
| **UI 前端** | 新建模型时**选**单位（对应 `DB.UNIT` 的 4 个字段；实测默认 `KN / M / KJ / C`） |
| **AI 建模 / 提示词** | **第 0 步先定口径**，之后所有步骤（材质 / 截面 / 坐标 / 荷载）**按该口径解释** |
| **核心** | **不**定义默认单位、**不**代填；缺单位 ⇒ **明确报错**（与 D2 的 `rw` 同口径） |
| **canonical** | 数值（`ELAST` / `DEN` / 坐标 / 力）的含义**由已确定的单位系统决定**，**不**写死 |

## 2. 落地（A–D 四项）

### A. 契约：新增 `MODEL.UNIT.ASSIGN`（Operation **70 → 71**）

```text
编排：steps = (PUT DB.UNIT, intent=write_unit, transformer=midas.unit.v1)
Tool：engineering_model_assign（**9 → 10**）
能力码：**新增** MODEL.UNIT.WRITE（词表 **41 → 42**，用户裁决 = C）
权限 / 风险：MODEL_WRITE · transactional=False · dry_run=True · recovery=STATE_RECONCILE
```

### B. 转换器：`midas.unit.v1`（`UnitSystemTransformer`）

```text
force → FORCE（required） · dist → DIST（required）
heat  → HEAT （required） · temper → TEMPER（required）
```

⚠️ **四个字段全部必填** ⇒ 缺一即 `transformer_required_field_missing`，**不**代填默认值。

### C. 载荷入口 + Seed

- `adapter.py` 的 `_build_payloads`：`write_unit ← parameters["unit"]`；
- `seed.py` 的 `OPERATIONS` 增一行；`operation_registry.OPERATION_COUNT` **70 → 71**；
- `capabilities.py` 的 `CAPABILITY_ENDPOINTS`：`MODEL.UNIT.WRITE → ("DB.UNIT",)`
  （**必需** —— 否则能力闸门判 `UNSUPPORTED`，实测报 `missing: ["MODEL.UNIT.WRITE"]`）。

### D. 旗舰链：第 0 步 = 先定单位

```text
⓪ MODEL.UNIT.ASSIGN（DB.UNIT）      ← **本批新增**
①′ 材质 · 截面 · 柱底节点 · 柱顶节点 · 单元 · 柱底固定
② 荷载（先建工况） · ②′ 荷载组合 · ③ 分析 · ④ 取位移 · ⑤ 设计（配置 4 步 + 验算 + 取表）
```

取值 = 该实例的**实测默认**（P157 `GET /DB/UNIT` = `{"FORCE": "KN", "DIST": "M", "HEAT": "KJ", "TEMPER": "C"}`）
—— 即"**显式**给出单位"，而不是让核心去猜。

## 7. 本批的教训

1. **"单位"这类输入不该由核心决定** —— 核心的职责是**承载**（一等步骤 + 必填字段 + 缺即报错），
   把"选什么"留给 UI / AI 提示词。**写死**看似省事，实为把**产品决策**埋进代码。
2. **新增能力码是"契约 + 词表 + 能力清单"三处联动**：只改 `Operation` 会在**能力闸门**处被拒
   （`missing: ["MODEL.UNIT.WRITE"]`），必须同时登记 `CAPABILITY_ENDPOINTS`。
3. **一步"先决条件"插到链首，会牵动全部顺序敏感的证据与用例** —— 与 R141（配置先于验算）同形；
   本批的连锁同步共 **40+** 处断言，**逐条**写明成因，**未**放宽任何判定。
