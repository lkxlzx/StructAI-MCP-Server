# P160b 报告：DOC 文件操作**必须带项目路径**（R143）—— 一次弹窗事故与核心守卫

> 批次：**P160b** ｜ 状态：✅ **已验收**（含一次**实测作废**与一次**回归修复**）
> 授权范围：`app/**` = **1** 个文件（`adapter.py`）+ **数据侧** 2 个 YAML（**退回**）
> 前置：P160a（旗舰链生产口径 12/12）

## 0. 一句话结论

1. ⚠️ **事故**：在**无项目路径**的新建项目上发 `POST /gen/DOC/SAVE` ⇒ MIDAS 弹出**「另存为」模态窗口**
   ⇒ **挂起 API、阻塞链路**（**由用户手动操作**才解除）。该次 `200` **不能**作为「生产可用」的证据
   ⇒ **判定作废**，`DOC.SAVE` / `DOC.CLOSE` 的 `availability` **退回 `untested`**。
2. ✅ **规则做进核心（R143）**：`DOC.OPEN` / `DOC.SAVE` / `DOC.SAVEAS` **必须带项目路径**；
   缺路径 ⇒ `STRUCTAI-1200` `project_path_required`，**一条请求都不发**（**实测零请求**）。
3. ✅ **形状修正**：`DOC.OPEN` / `DOC.SAVEAS` 的体**就是路径字符串**（手册 `{"Argument": "<路径>"}`）
   —— `_arguments_step` 不再把体强制成对象。
4. ⚠️ **抓到并修掉一个生产回归**：守卫最初**漏了提前返回** ⇒ `DOC.NEW` 也被要求路径
   （由既有用例 `test_p123_requests_follow_the_registry_wrapper_and_path_key` 抓到）。

## 1. 事故经过（如实记录）

### 1.1 用户给出的产品规则

> **前端 UI 中有"设置项目文件夹"，文件操作都在项目文件夹内；保存及另存必须带项目路径，
> 不然会弹出「另存为」窗口，这会挂起 API 造成 API 链路阻塞。**

### 1.2 我犯的错

P160b 的第一次有界实测，顺序是：

```text
NEW → 建 1 个节点 → **SAVE（无路径）** → CLOSE → NEW
```

`DOC.SAVE` 回了 `200`，我据此把 `DOC.SAVE` / `DOC.CLOSE` 收口为 `verified`。
**但真相是：那次 `SAVE` 弹出了「另存为」模态窗口，是用户手动处理掉的** ——
⇒ 我当时的判据「回了 `200` 就算通过」**漏掉了副作用**；而 API 之所以还活着，是**人工干预**的结果。

### 1.3 处置

1. **撤回**：`DOC.SAVE` / `DOC.CLOSE` 的 `availability` 退回 `untested`，YAML 里**写明作废原因**；
2. **规则前移**：把"必须带项目路径"做进核心（下节）；
3. **判据修正**：**"端点可达" ≠ "调用安全"** —— 有副作用的端点，判据必须包含**副作用**。

## 2. 核心守卫（R143）

### 2.1 规则

```text
DOC.OPEN   / DOC.SAVE / DOC.SAVEAS  必须带项目路径
  缺路径 ⇒ STRUCTAI-1200 project_path_required（**发请求之前**拦住）
  理由：否则 MIDAS 弹「另存为」模态窗口 ⇒ **挂起 API、阻塞链路**
```

### 2.2 形状（手册口径）

| 端点 | 请求体 | 说明 |
| --- | --- | --- |
| `DOC.OPEN` | `{"Argument": "<路径>"}` | 体**就是**路径**字符串** |
| `DOC.SAVEAS` | `{"Argument": "<路径>"}` | 同上 |
| `DOC.SAVE` | `{"Argument": {}}` | 路径由**项目自身**持有 ⇒ 核心只做**前置断言**，**不**塞进体里 |

⚠️ `_arguments_step` 原先 `body = dict(arguments)`（**强制对象**）⇒ `OPEN`/`SAVEAS` 的**字符串体**
根本发不出去。本批改为 `body = arguments`（**不**再强制）。

### 2.3 为什么 `SAVE` 只做"断言"而**不**把路径塞进体

`DOC.SAVE` 的手册体是 `{"Argument": {}}`；路径来自**项目当前持有的文件**。
⇒ 核心**无法**核实"该项目确实有路径"（那要读原生状态），因此：

- 调用方（UI / AI）**必须**给出 `project_path`（表示"该项目已有路径"）；
- 核心据此**放行**并发送手册体 `{}`；
- ⚠️ **若项目其实没有路径**（如刚 `NEW` 的空项目），原生**仍会弹窗** ⇒ 故本批**只**做了一次
  **安全**的实测（缺路径 ⇒ 零请求），**没有**去发"带路径但项目无路径"的 `SAVE`。

## 3. 实测（真机，**安全**口径）

```text
--- OPEN（**无** project_path）---   请求数 = 0   STRUCTAI-1200 project_path_required（DOC.OPEN）
--- SAVE（**无** project_path）---   请求数 = 0   STRUCTAI-1200 project_path_required（DOC.SAVE）
--- SAVE_AS（**无** project_path）-- 请求数 = 0   STRUCTAI-1200 project_path_required（DOC.SAVEAS）
```

⇒ **守卫确实在发请求之前拦住** ⇒ **不**会弹窗 ⇒ 事故形态被从根上消除。

**离线用例**（`tests/test_midas_doc_path_guard_p160b.py`，**10** 项）：三个端点缺路径 ⇒ 拒绝；
空白路径同判；`OPEN`/`SAVEAS` 的体是**字符串**；`SAVE` 的体仍是 `{}`；
**`DOC.NEW` 不**被要求路径（回归钉子）。

---

## 4. 回归（本批最有价值的一条）

守卫的第一版**漏了"非文件操作直接返回"**的提前分支 ⇒ **`DOC.NEW` 也被要求路径**。
这在**生产**里会让"新建项目"直接失败 —— 而它是 P158 刚收口的端点。

**是既有用例抓到的**（`test_p123_requests_follow_the_registry_wrapper_and_path_key`，它真的执行 `NEW`），
不是我自己看出来的。⇒ 处置：

1. 加提前返回（`step.key not in DOC_PATH_OPERATIONS` ⇒ 原样发对象体）；
2. **加强**我自己的用例：不只断言常量，而是**真的调用** `_doc_arguments(NEW, {}) == {}`。

**教训**：**只断言常量的测试等于没测**；守卫类改动必须**真的走一遍被守卫的调用**。

## 7. 本批的教训（按重要性）

1. **有副作用的端点，"回了 `200`"不是通过判据** —— `DOC.SAVE` 回了 `200` 却弹了模态窗口。
   判据必须包含**副作用**（本批靠用户告知才发现，代价是用户手动处理了一次弹窗）。
2. **产品规则要前移进核心**：用户知道"无路径会弹窗"，核心就该**先拦**，
   而不是让每个调用方各自记住 —— 这正是"核心写好"的意义。
3. **只断言常量的测试等于没测**：守卫漏了提前返回，常量断言照样绿；是**真的走一遍调用**的既有用例抓到的。
4. **回退要留痕**：作废的收口**不**悄悄改回去，而是在 YAML 里写明**为什么作废**。
