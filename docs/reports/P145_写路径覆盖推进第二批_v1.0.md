## 2. 两种**声明式**救回（不新开机制、不改判据）

### 2.1 `DB.LENG` / `DB.MBTP`：按**构件号**取值 → 前置链 + `target_id_source`

**事实**：两者的手册示例 `Assign` 键分别是 `21` / `160`（**构件号**），空项目里没有构件 ⇒
原样照抄得到 `400 Not Found Key`（`DB.LENG` 实测；`DB.MBTP` 同形）。

**救回（全部用既有机制）**：加前置链 `DB.MATL#1` + `DB.SECT#1` + `DB.NODE#1/#2` + `DB.ELEM#1`
（前置的编号引用都指向 `DB.ELEM#1` 的 body：`MATL` / `SECT` / `NODE[0]` / `NODE[1]`），
并用 **R96** 的反向依赖让**目标自身**的 `Assign` 键取该单元的**实分配**编号：

```json
"target_id_source": "DB.ELEM#1"
```

⇒ 目标 `body` **原样**照抄手册示例（`kind = manual_example`、`adjustments: []`、无 `self_references`）。
实测 `29 / 29` 中两者均 `PASSED`（`created_id = 1` = 自建单元的编号）。

### 2.2 `DB.MVHLTR`：示例**条目 1** 缺必填字段 → 改用**条目 2**

**事实**：手册示例 `Assign` 下有**两个条目**。条目 1 缺 `ML` / `MW` / `LEFT_LANES`
（规格表标 `Required`）⇒ `400 Wrong Field`；条目 2 自带这三个字段。二分实测：

| 变体 | 结果 |
| --- | --- |
| 条目 1 原样 | `400 Wrong Field` |
| 条目 1 去掉 `DE` | `400 Wrong Field` |
| 条目 1 去掉 `OPT_MEDIAN_STRIP` | `400 Wrong Field` |
| 条目 1 **补** `ML` / `MW` / `LEFT_LANES` | **`200`**（创建 → 读回 → 删除全通） |
| 条目 2 原样 | **`200`**（创建 → 读回 → 删除全通） |

⇒ **只把 `source.example_id` 由 `"1"` 改 `"2"`**（仍是 `manual_example`、**无** adjustments）。
⚠️ `adjustments` **只**能改**值**、**不能**加字段 ⇒「补字段」这条路在数据侧**不可表达**，
而手册**自带**可用的条目 2 ⇒ 走「换条目」而不是「留缺」。

## 3. 新裁决 **R102**：`DB.HPCE` **如实留缺**（带原生证据）

`POST /DB/HPCE` 的**六种**键形态（`gen-local` 实测）：

| 形态 | 结果 |
| --- | --- |
| `{"Assign": {"1": <手册示例 body>}}` | `400 Wrong Key` |
| `{"Assign": {"2": ...}}` | `400 Wrong Key` |
| `{"Assign": {"1": ...}}`（无 `START_TIME` / `END_TIME`） | `400 Wrong Key` |
| `{"Assign": {"1": ...}}`（`ITEMS: []`） | `400 Wrong Key` |
| `{"Assign": {"1": ...}}` + `ITEMS` 指向**已建**节点 `1` / `2` | `400 Wrong Key` |
| `{"Assign": {"PC1": ...}}`（**名字**键） | `200` 但**静默不落库**（`GET /DB/HPCE` 仍 `{}`，即使 `ITEMS` 指向**已建**节点） |
| `{"HPCE": {...}}` / `{"Argument": {...}}` | `400 Wrong Field` |

**判读**：该端点的 `Assign` 键**不是**编号（数字键一律被拒），而**名字**键被 JSON 层**静默丢弃**
（`200` + 空体 + 不落库）。模板机制里 `target_id_source` / `self_references` **只**写回**整数**编号，
`adjustments` **只**能改**值** ⇒ 数据侧**无法**表达 ⇒ **模板不写、不入候选**。

**同时证明这不是数据侧缺陷**（可执行断言）：端点仍 `enabled = true`、`availability = verified`、
`methods` 含 `POST` / `GET` / `DELETE`，且手册示例的**每个字段**都在数据侧请求 Schema 里声明
（`tests/test_midas_write_coverage_p145.py::test_p145_hpce_is_honestly_left_out_with_native_evidence`）。

⚠️ **留待显式裁决**：`DB.HPCE` 的**写侧产品覆盖**（是否收窄 GEN NX 的写方法 / 是否在 `civil-cloud` 上可写）
—— 本批**不**动 `products`（那会连带影响**只读**可得性），也**不**改判定。
