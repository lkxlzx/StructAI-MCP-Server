## 1. R106：`POST.*` 结果表 / 文本查询的**取报表判据**

### 1.1 为什么必须另立判据

`docs/07` §16 R4 / R14 的 **L5 三步链**是「创建 → 读回 → 按路径 key 删除」。`POST.*` 的
**197** 个端点（GEN NX：`POST.TABLE.*` **194** + `POST.PM` / `POST.TEXT` / `POST.STEELCODECHECK`）
**只**有 `POST`、**没有** `GET` / `read_root` ⇒ **没有「自建 ID」可读回、可删** ⇒ 三步链
**结构上不适用**，此前一律落在「无读回」桶里、**从未取得结论**。

### 1.2 侦察（先做只读 / 无副作用，两个问题都要答案）

| 问题 | 实测答案（证据） |
| --- | --- |
| ① 是否需要**已分析**的模型？ | **是**。空项目下 `POST /POST/TABLE` + `{"Argument": {"TABLE_TYPE": "AXISYMMETRICFG"}}` → **`400 "[empty] Cannot generate table data as there is no analysis result."`** ⇒ 判据**必须**带**最小模型前置链**（**不**放宽） |
| ② 响应是否真的**只读**（不写模型数据）？ | **是**。最小模型下逐端点发查询，跑前 / 跑后 **7** 个模型哨兵（`NODE` / `ELEM` / `MATL` / `SECT` / `STLD` / `CONS` / `BMLD`）**逐条相同** ⇒ 取报表**零副作用** |

### 1.3 判据（`registry/README.md` §8.13）

1. **前置链** = 最小模型（`MINIMAL_MODEL`，**只**用自建编号 `1` / `2`，共 **8** 个对象）+
   `POST /DOC/ANAL`（`Argument` 空体 = 执行分析）；
2. **请求体** = 上游手册（两个来源合并）里该端点**自己那张表**的示例，**唯一**改动 =
   **剥掉 `Argument.EXPORT_PATH`**（带它会让实例**落文件**）；改动逐条记进证据的 `adjustments`，
   body 另存 `sha256`（**不**落原文）；
3. **判定** = `HTTP 200` ∧ **实测信封形状**（**恰好 1 个**顶层键 ∧ 其值是**对象** ∧ 同时含
   `HEAD` 与 `DATA` 两个**数组**）⇒ `PASSED`；`200` ∧ **空块**（`{}` 或 `{"message": ""}`）⇒
   `PARTIAL`（该表在最小模型上**无数据**，与 P134 的 `EMPTY_BLOCK_KEY` 同口径）；其余 ⇒ `FAILED`；
4. **零残留** = 跑前 / 跑后哨兵**逐条相同**；跑完**逆序**清理自建模型，清理后哨兵**全空**。

⚠️ **信封键逐端点不同**（**不**是全局常量）—— 实测到 `Example`（10 个）之外还有
`ElementPropertiesatEachStage` / `TendonGroup` / `TendonProfile` / `TendonProperty`（表自己的名字）
与 `empty`（该表的**字面**键名）。故判据**只**断言**形状**，并把**实测到的键**逐条记进证据
（`envelope_key`）后落成该端点的 `response` 块。

⚠️ **示例定位**（逐条可复算）：`table_type` 非空 ⇒ 按 `Argument.TABLE_TYPE`（或 `TEXT_TYPE`）
精确匹配；否则按**端点 `title`** 与示例名（剥掉尾部 ` #<n>`）做前缀匹配；仍多解 ⇒ 取字典序第一个
并记 `example_id`。`POST.TABLE.string`（`table_type` 为空）按标题定位到
`Concrete Design - Beam Design Forces #1`（即 `BEAMDESIGNFORCES` 那张表）—— **只**代表该表。

## 2. R107：无 `DELETE` 的单例 / 设置表的**取设置表判据**

### 2.1 目标集与前置闸门

GEN NX 上**无 `DELETE`** 的端点共 **14**（`GET` + `PUT` **11** · `GET` + `POST` **3**：
`OPE.SECTPROP` / `OPE.STORY_IRR_PARAM` / `OPE.STORY_PARAM`）。三步链第 3 步走不通 ⇒ 另立判据。

⚠️ **前置闸门（**先**做，只读）**：`GET <uri>` 必须返回**非空**原值
（`{<read_root>: {"1": {…}}}`）。**实测**：空项目下 `GET /DB/PZEF` → **`{}`**，而 `PUT` 会
**创建**一条记录、且该端点**没有** `DELETE` ⇒ **无法还原** ⇒ 这类端点**必须**如实留缺
（`empty_singleton_put_creates_undeletable_record`，**绝不**发 `PUT`）。这是**零残留纪律**的硬约束。

### 2.2 判据与实测

**判据** = 「读回原值 → `PUT` **改动过**的值（手册示例）→ 读回确认**改动生效** →
`PUT` **还原**原值（逐字段照抄跑前读回）→ 读回确认**逐字节**等于原值」。

| 结论 | 条数 | 端点 / 原因 |
| --- | --- | --- |
| `PASSED` | **2** | `DB.STYP` · `DB.UNIT`（改动生效 ∧ **逐字节**还原 ⇒ **零残留**） |
| `FAILED`（**空原值闸门拒绝发 `PUT`**） | **7** | `DB.CLDR` · `DB.CO_F` · `DB.CO_M` · `DB.CO_S` · `DB.CO_T` · `DB.MATD` · `DESIGN.RC.KDS-41-20-2022.SRDF` |
| 留缺 | **5** | `DB.PZEF`（空原值，已实测）· `DB.CPSETTINGS`（无手册示例）· `OPE.SECTPROP` / `OPE.STORY_IRR_PARAM` / `OPE.STORY_PARAM`（无 `PUT`） |

⚠️ **子桶口径**：本判据的结论**单独成桶**（`no_delete_singleton`），**不**并入 L5 三步链的
覆盖率分子；**原口径照旧报出、不过滤、不隐藏**（这 14 个端点本来就不在 `candidate_keys()` 里 ——
无 `DELETE`）。把子桶升格为正式分母需要一次**显式裁决**，本批**不**做。

产物：`registry/tools/probe_singleton_tables.py`（**新**）·
`registry/live/singleton_table_probe.json`（**新**）·
`tests/test_midas_singleton_tables_p149d.py`（**新**，7 项）。

### 2.3 ⚠️ 残留如实披露（**不**声称零残留）

侦察阶段（**判据之外**）对 `DB.PZEF` 发过一次 `PUT`（写入手册示例的值
`{"OPT_OFFSET": true, "OFFS_FACTOR": 1.0, "OUTPUT_POSITION": 1}`）—— 该端点 `GET` 原值是 `{}`、
**没有** `DELETE`，事后确认**无法清除**：

- `PUT /DB/PZEF {"Assign": {}}` → **`200`**（响应 `{"PZEF":{}}`）但 `GET` **读回仍在**；
- `PUT /DB/PZEF {}` → `400 Wrong Field`。

⇒ 该记录是**侦察残留**，如实记入本报告与证据（`NEVER_PUT_EMPTY_ORIGINAL` 的 docstring）。
**其余**端点（`DB.UNIT` / `DB.STYP`）已**逐字节**还原；模型哨兵（`NODE` / `ELEM`）**全空**。

## 4. R112：`request_schema()` 支持四种请求形状 ⇒ 字段白名单检查**不再空判**

### 4.1 修的是什么

`registry/tools/check_write_templates.py::request_schema()` 旧版**只**认
`{"properties": {"Argument" | "Assign": …}}`。`registry/schema/**` 实测还有三种形状：

| 形状 | 例 | 旧版行为 |
| --- | --- | --- |
| 根 `properties` 里的包装键 | `schema/common/db/REBB.json`（`Assign.patternProperties['^[0-9]+$']`） | ✅ 可判（P149-B2 修） |
| **根级包装** | `schema/common/db/LENG.json`（`{"$schema": …, "Argument": {…}}`，来自 `/info/db/<CODE>` 自省） | ❌ **空判**（`unknown_fields()` 恒返回 `[]`） |
| **按端点代码键控** | `schema/common/db/SECT.json`（`{"SECT": {…}}`）；根键名与端点代码**不同**的 `products/gen_nx/db/MBTP.json`（单根键 `TABLE`）；条目字段**直接平铺**的 `common/db/VSEC.json` | ❌ **空判** |

**修前：63 / 71 个模板的字段白名单检查是空判**（恒真 = 等于没查）。**修后：71 / 71 全部非空判**
（逐条复算：**0** 个空判 · **0** 个未知字段）—— 判定**变强**，**不**放宽（**未**新增任何白名单）。

### 4.2 裁决（**R112-A：补 Schema**）

修完后立刻暴露 **`DB.SECT.SECT_BEFORE.{DATATYPE, SECT_I}`**：它们出现在**手册示例**
（模板来源）里，而数据侧请求 Schema **没有**声明 ⇒ 缺口**在数据侧**。

**裁决 = 补 Schema**，理由（两条独立机械来源）：

1. 该 body 是**逐字节**的手册示例，且该端点实测 **`PASSED`**（本 build 接受这两个字段）；
2. 端点定义里**已登记** `schema_ref.introspect: info/db/SECT`，**只读自省** `GET /info/db/SECT`
   （实测 `200`）**逐字声明**这两个字段（`DATATYPE` = `integer`；`SECT_I` = `object`，含
   `SHAPE` / `DB_NAME` / `SECT_NAME` / `SECT_NAME2` / `vSIZE` / `PERIIN` / `PERIOUT` /
   `BUILT_FLAG` / `BEFORE_PART_NUM` / `USE_SYM_CALC` / `CF_STIFF_ULS`）。

⇒ **只**补模板**实际用到**的这两个字段（取自省原文），**不**引入自省里其余 **55** 个字段
（它们没有模板用到，属另一类「Schema 覆盖不全」缺口，**另记**，本批**不**自动应用）。

`tests/test_midas_write_templates_p149b2.py` 里「钉住旧现状」的用例已**反向**改成断言**更强**的
行为（臆造字段**必须**被报出、已声明字段**不**得误报）。
