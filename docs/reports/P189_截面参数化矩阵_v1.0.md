## 1. 为什么用 vSIZE 缩放（而不是真实 H 型钢）

⚠️ **R151 红线**：真实 H 型钢的 `DBUSER` 截面 `SHAPE` / `vSIZE` 语义（哪个 SHAPE 值对应 H 型、vSIZE 各元含义）在本仓**无权威来源**，实例 `/info/db/SECT` 也只给 `string`/`number[]` 不给枚举 ⇒ **不臆造真实钢号尺寸**。

因此本轮做 **vSIZE 缩放机制验证**：同一模型、同一荷载，只改截面 `vSIZE`（`[1,1]` → `[5,5]` → `[10,10]` → `[20,20]`），
验证「**截面参数变化 ⇒ 设计承载力 / 挠度随之变化**」。这证明参数化在**截面维度**成立；真实 H 型钢待权威 vSIZE 定义加入即用。

## 3. 一屏看出的规律（参数化截面维度的价值）

1. **弯矩需求 My ≈ 恒 440000**：同跨度同荷载，**与截面无关**（物理正确 ✓）。
2. **承载力 Mcap 随截面尺寸单调、高次增长**：47k → 5.9M → 47M → 380M。
3. **挠度 uz 随截面增大而骤降**：−0.133 → −0.00056 → −0.0001 → −2.3e−5（截面越大越刚，物理正确 ✓）。
4. **设计 NG → OK 的临界**：`[1,1]` 太小（NG），放大即 OK ⇒ **参数化能直接定位「多大的截面能通过」**。

> 这证明：**截面参数真的驱动设计**（不是摆设），参数化框架在截面维度完整可用。

## 4. 机制（如何加真实 H 型钢用例）

`_beam_steps_via(..., section_shape, section_vsize, section_secttype)` 已支持截面参数化；
`SECTION_MATRIX` 用例表每项可带 `section_shape` / `section_vsize` / `section_secttype`。
**一旦拿到权威 H 型钢定义**（如 `SHAPE="H"` + `vSIZE=[H,B,tw,tf,...]`，来自 MIDAS 截面库/手册），
在 `SECTION_MATRIX` 加一行真实截面即可批量扫「截面 × 跨度 × 荷载 → GB50017 是否通过」的真实选型矩阵。

```bash
# 截面 vSIZE 缩放矩阵
python registry/tools/_run_with_env.py gen registry/tools/probe_beam_chain_p189.py --matrix --matrix-kind sections
# 跨度/荷载矩阵
python registry/tools/_run_with_env.py gen registry/tools/probe_beam_chain_p189.py --matrix --matrix-kind beam
```
