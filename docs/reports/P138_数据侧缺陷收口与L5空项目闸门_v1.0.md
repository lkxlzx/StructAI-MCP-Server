## 3. P138b —— R5：20 个无 Schema 端点按实测分类

**不**臆造、**不**新增文件（`registry/schema/**` 仍 **616** 个）。判据全部来自数据文件本身：

| 类 | 条数 | 端点 | 判据（可执行） |

⚠️ **与旧提示词分组不同的两处**（以实测为准）：

1. `OPE.MEMB` / `OPE.STOR` / `OPE.STORPROP` / `OPE.STORY_*_PARAM` 的手册条目**就是同一个 URI**
   （`ope/MEMB` / `ope/STOR` / `ope/STORPROP` / `ope/STORY_*`）—— 不是「手册有同名端点但 URI 不同」；
   它们是「手册有该 URI 但没有 `json_schema`（只有参数表）」。
2. `OPE.STORPROP` 在手册里**有**同 URI 条目 —— 旧提示词把它归入「手册完全没有」不成立。

### 3.1 顺带裁决：`request_schema_confirmed` 对**无请求体**端点「不适用」

`methods` 不含 `POST` / `PUT` / `PATCH` 的端点**没有请求体**，把「没有请求 Schema」判成缺口是**类别错误**
（会让这类端点**永远** `PARTIAL`）→ 该项**视为满足**，由 `live.not_applicable_items()` **如实**报出
（`has_request_body()` / `not_applicable_items()` 是可执行判定）。

| 端点 | 改动前缺项 | 改动后缺项 | `verification_status` |
| --- | --- | --- | --- |
| `OPE.PROJECTSTATUS` | `request_schema_confirmed` + `response_schema_confirmed` | **`response_schema_confirmed`**（真实缺口：没有 Schema 文件 → 没有 `response` 块） | `PARTIAL`（**未**升级） |
| `OPE.SECTPROP` / `VIEW.SELECT` | 同上 | 同上 | `PARTIAL`（**未**升级） |
| `OPE.STORY_PARAM` / `OPE.STORY_IRR_PARAM` / `OPE.MEMB` / `OPE.STOR`（带 `POST`） | 缺 `request_schema_confirmed` | **仍缺**（裁决只覆盖无请求体端点） | 不变 |

判定口径**未改**：`verification_status` 仍只由 `availability` 机械映射（`docs/07` §7.2 / §16 R78）。
