## 1. R118 续跑：带前置链的「编辑（PUT）」判据

### 1.1 前置链机制（**沿用 L5**，不重写判定点）

* **声明来源唯一**：`prerequisites` / `references` / `self_references` / `target_id_source` /
  `id_source` **只**由 `app/infrastructure/adapters/midas/write_templates.py` 解析
  （工具 `load_templates()` 直接复用它，**不**另写一份解析规则）。
* **编号一律重新分配**（与 L5 的 `_plan` 规则**逐条一致**）：前置编号 = 该端点既有编号的
  `max + 1`（同一端点的多个前置按声明顺序依次 `+1`）；`id_source = "target"` 的前置取**目标**
  编号；目标可用 `target_id_source` **反向**取某个前置的编号（`DB.CONS` / `DB.CNLD` /
  `DB.LENG` / `DB.MBTP` / `DB.NMAS`）。
* **等价性可执行判定**：`tests/test_midas_put_edits_p151.py::test_p151_the_chain_planning_is_equivalent_to_l5`
  把工具的 `plan_chain()` 与 L5 的 `MidasLiveWriteProbe._plan()` 在**空项目**与**非空**两种
  快照上**逐条**比对（目标编号 + 每个前置的编号 + 每个请求体**逐字节**）—— **15 / 15 全等**。
* **纪律**：目标创建**之前**按声明顺序建前置；目标清理后**逆序**回收；删除**一律**以
  「**再读确认不在**」为准（R119，**不**信状态码）。

## 2. R120 工具化：别名路由的**实测**与**可复算**收尾

### 2.1 判据（先写清楚再动手）

| 步 | 判据 |
| --- | --- |
| ① | 跑前哨兵（**72** 个端点）必须为空（已披露残留可 `--allow-residue` 放行） |
| ② | 自建编号 = **两个**路由既有编号的 `max + 1`（空 ⇒ `1`）；**只**碰自建编号 |
| ③ | 经**别名路由**创建 ⇒ 该编号**必须**出现在同表 `DB.*` 路由的读回块里 ⇒ `same_table_observed` |
| ④ | 别名路由 `DELETE` → **再读**（记录仍在 ⇒ `alias_delete_effective = false`） |
| ⑤ | 同表 `DB.*` 路由 `DELETE` → **两个**路由再读**都**不在 ⇒ `db_delete_effective` / `delete_confirmed` |
| ⑥ | 清理失败 ⇒ 如实记 `delete_confirmed = false` 并进 `residue`（退出码 1） |

### 2.2 实测（`--probe-aliases`，自建编号，**当批**实测 ⇒ 映射**来自实测**、**不**臆造）

| 别名路由 | 同表 `DB.*` 路由 | `same_table_observed` | 别名路由 `DELETE` | `DB.*` 路由 `DELETE` | `delete_confirmed` |
| --- | --- | --- | --- | --- | --- |
| `/DESIGN/RC/DRC` | `/DB/DCON` | **true** | `200` 但**记录仍在**（**不生效**） | `200` 且**两路由再读均不在** | **true** |
| `/DESIGN/RC/KDS-41-20-2022/DCTL` | `/DB/DCTL` | **true** | `200` 但**记录仍在** | `200` 且**两路由再读均不在** | **true** |
| `/DESIGN/STEEL/DSTL` | `/DB/DSTL` | **true** | `200` 但**记录仍在** | `200` 且**两路由再读均不在** | **true** |

* **「删除已确认」/「别名清理已确认」/「删除未确认」三态**（逐行 `delete_state`）：
  * `delete_confirmed` —— 本端点路由的 `DELETE` **再读确认**该编号不在（PASSED 的 42 行 + 其余成功行）；
  * `delete_confirmed_via_alias` —— 本端点路由**删不掉**，但**同表 `DB.*` 路由**清理后
    **两个**路由再读均不在（上面 **3** 个）；
  * `delete_unconfirmed` —— 所有已实测手段都删不掉 ⇒ **如实记残留**
    （`DESIGN.SRC.AIK-SRC2K.DSRC`，**R121**：该端点**没有** `DB.*` 别名）。
* **收尾步骤可复算**：`--check` 离线断言 `alias_cleanup` 与逐行状态**自洽** ——
  候选键集、`alias_uri` / `db_key` / `db_uri`、`measured` / `same_table_observed` /
  `alias_delete_effective == false` / `db_delete_effective == true`、`delete_confirmed` 与
  `delete_state` 一致、**删除已确认不得留残留**、**删除未确认必须在 `residue` 里如实披露**。
* ⚠️ **成因仍需 MIDAS 侧**：别名路由的 `DELETE` 为何返回 `200` 却不删（R120 的**结论未变**，
  本批只把**清理路径**工具化）。
