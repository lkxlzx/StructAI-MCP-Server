## 1. 项目定位与资产盘点

### 1.1 定位

面向**多结构工程软件**的通用、**软件无关** MCP Server。向上对 AI 客户端暴露 **9 个稳定的工程语义 Tool**；向下通过
**Adapter** 驱动具体工程软件（当前接入 MIDAS CIVIL NX / GEN NX / Civil Designer，后续支持
ETABS / SAP2000 / ANSYS / OpenSees）。核心解耦：**Tool ≠ API** —— AI 只需知道 `BUILD.COLUMN`，不需知道 `/db/ELEM`。

## 2. 架构冻结要点

### 2.1 三层解耦

```
MCP Client → Tool(9) → Operation(69) → Capability → API Registry → Adapter → 工程软件
```

### 2.2 依赖方向（冻结）

```
Interface → Application → Domain
Infrastructure → Domain / Application Interfaces
```
**禁止反向**。`Domain` 不得引用 SQLAlchemy / FastAPI / MCP SDK / httpx。

### 2.3 架构红线（`02` impl §57 / blue §1.2 / source7 §136）

| 禁止 | 说明 |
| --- | --- |
| `Tool → Native API` | Tool 不得直接调 MIDAS / SQLAlchemy / httpx / 厂商 SDK |
| `Tool → SQLAlchemy` | Tool 只调 Application Service |
| `UI → Database` / `AI → Native API` | 不得绕过 Core |
| `Adapter → FastAPI` | Adapter 不得依赖 Web 框架 |
| `Client → forged IdentityContext` | 客户端不得伪造身份 |
| `Database → executable Python` | 禁止从 DB 执行任意代码 |
| `Domain → MIDAS` | Domain 不认识任何厂商 |
| 命名禁令 | `midas_xxx()` / `midas_api()` / `midas_endpoint()` / `midas_node_create()` / `midas_analysis_static()` |
| `grep -R "midas" app/` | 预期 **0** 处 MIDAS-specific 业务依赖 |

### 3.3.1 传输层落点裁决（**P40–P41 新增**，2026-10-07）

`docs/03` §80（Core Alpha 目录形状）要求在 `app/interfaces/mcp/` 下增加
`protocol.py` / `session.py` / `authentication.py` / `progress.py` /
`cancellation.py` 与 `transport/{base,stdio,http}.py`，而 §3.3 的冻结结构里**没有**
传输文件。P40–P41 据此**裁决落点**如下（冻结结构因此显式增补，不是悄悄偏离）：

| 规范章节 | 落点 | 说明 |
| --- | --- | --- |
| `docs/03` §3（Transport 抽象）· §20–§24（限制）· §25–§34（协议）· §63（错误信封） | `app/interfaces/mcp/transport/base.py` | `MCPTransport` 四方法抽象 · `MCPRuntimeLimits` · 与 SDK low-level `Server` 的适配（`tools/list` / `tools/call`） |
| `docs/03` §40–§43（STDIO Transport / 骨架 / 日志 / 安全） | `app/interfaces/mcp/transport/stdio.py` | `StdioTransport` / `run_stdio`；协议帧与 stdout 纪律由 SDK 的 `stdio_server()` 承担 |
| `docs/03` §44–§59（Streamable HTTP 全节） | `app/interfaces/mcp/transport/http.py` | `StreamableHTTPTransport` / `MCPHTTPMiddleware` / `build_http_app`；协议与会话表由 SDK 承担，鉴权 / 会话绑定 / 限额 / 限流 / 超时由本层守门 |
| `docs/03` §16 · §22–§24 · §47–§49 · §52–§55 · §57 · §59 | `app/interfaces/mcp/transport/http_session.py` | 会话绑定表 / 限流器 / 在途计数 / body 限额（HTTP 的会话与限额**原语**） |

**为什么另开 `transport/` 包而不是复用 `interfaces/http/`**：`docs/02` §95 明确
HTTP 管理面（`/livez` / `/readyz` / `/health`）与 MCP 是**并列的两条对外面**，
MCP 的 HTTP 面不是管理 API；且 `docs/03` §80 的目录形状本身就要求
`interfaces/mcp/transport/`。故传输层归 `interfaces/mcp/`，`interfaces/http/`
保持只做管理 / 健康面。

**为什么不另建 `protocol.py` / `session.py` / `progress.py` / `cancellation.py`**：
`docs/03` §41 / §46 逐字要求「wire framing 必须由采用的 MCP SDK/协议实现负责」、
「各方法的语义由 MCP SDK/协议版本决定，不要在 Core 中写死」。本批因此把
JSON-RPC 编解码、`initialize` / `ping` / 会话生命周期交给 SDK 的 low-level
`Server` 与 Streamable HTTP 会话管理器，只把「协议 ↔ `MCPServer.handle()`」的
转换留在 `base.py`；`progress` / `cancellation`（§35–§39）与 `tools/list` 的分页
留待后续批次，**不在本批伪造**。

| **Batch** | query/assign/result=必须；delete/build/design/analysis=支持；view=可选 |
| **事务回滚优先级** | Native Transaction → Snapshot/Restore → Compensating Actions → Best Effort |

> 钢 `GB50017-03`、`GBJ17-88`、`JTJ025-86`；桥涵 `JTG 3362-2018`、`JTG D62-04`、`CJJ 11-2019`、`TB 10092-2017` 等。

> `AISC360-16` / `EN1992-1-1` / `AIJ` 在 gen-local 与 civil-cloud 上**全部 404**；
> 且交叉约束有效：`/DESIGN/RC/KDS-41-30-2022/DCO` → 404（钢规范不能用于 RC）。

**支持集如何确定（两段式 —— 已定为机制）**

1. **静态候选集** = `registry/design_codes.yaml`（155 条，逐行抽自官方手册枚举表；工具 `registry/tools/extract_design_codes.py`）。
   API **不提供**支持集枚举：`/info/db/DCON` 返回的 schema 里 `DGNCODE` 是 `type: string`（**无 `enum`**）；
   裸路径 `/DESIGN`、`/DESIGN/RC`、`/DESIGN/RC/KDS-41-20-2022` 一律 404，无法列子节点。
2. **运行时探测** = Adapter 连接时用候选集执行 `GET /DESIGN/{material}/{code}/DCO`：
   `200` 支持 / `404` 不支持；**零副作用**；结果只存连接会话，**不落盘**。
3. **读当前生效值** = `GET /db/DCON` / `GET /db/DSTL` / `GET /db/MODULE`
   （空项目返回 `{}` 或 `{"message":""}`，属正常空表，不是错误）。

**Core 侧约定（不违反架构红线）**：`code` 在 Tool 契约里保持**自由字符串**，
Core 内**不出现任何厂商规范名**；「请求的 `code` 是否可用」由 Adapter 用探测结果做前置校验，
不通过则返回 `CAPABILITY_UNSUPPORTED`。

> ⚠️ `docs/03` §68/§69/§70 的示例用的是 `GB50007` / `GB50017` / `GB50010`（中国规范名）。
> 这些是**契约示意值**，不是可执行值 —— 实际可用值以上表 A/B/C/D 的实例探测结果为准
> （例如钢的可用中国规范是 `GB50017-03` 与 `GBJ17-88`，**没有** `GB50017-2017`；
> 基础规范 `GB50007` **在任何一套里都不存在**，故 `DESIGN.FOUNDATION` 只能自研）。

### 7.2 Registry 接入（**我们的数据 → 文档规定的 3 张表**）

`docs/04` §9 定义了 7 张表，其中 3 张有字段定义。映射方案：

| 目标表 | 数据来源 | 映射规则 |
| --- | --- | --- |
| `midas_api_sources` | `registry/manifest.json` 的 `source.url` + `provenance` + `retrieved_at` | 按 `(source_url)` 去重；`product` 取端点 `products`；`category` 取 `namespace` |
| `midas_api_endpoints` | **`registry/manifest.json` 的每个端点** | `path` ← `uri`；`method` ← `methods` 展开为多行；`category` ← `namespace`；`product` ← `products`；**`verification_status` ← `availability`**（`verified`→`VERIFIED`，`unverified`→`UNVERIFIED`，`untested`→`PARTIAL`）；`deprecated` ← `enabled === false` |
| `midas_api_schemas`（请求方向） | **`registry/schema/**/*.json`** | `schema_uri` ← `midas://<product_lower>/<code_lower>/request/v1`；`direction`=`request`；`schema_json` ← 文件内 `schema` 字段 |
| `midas_api_schemas`（**响应方向**，P137a） | **同一份文件的 `response` 块** | `schema_uri` ← `midas://<product_lower>/<code_lower>/response/v1`；`direction`=`response`；`schema_json` ← `response.schema`（**未声明 → 不建行**）；并回填 `midas_api_endpoints.response_schema_id` / `midas_api_mappings.response_schema` |

**`availability` → `verification_status` 的映射规则**（关键）：

```
registry.availability == "verified"   →  VERIFIED    （246 个端点，可直接进生产）
registry.availability == "unverified" →  UNVERIFIED  （23 个，禁止在生产使用）
registry.availability == "untested"   →  PARTIAL     （367 个，需补 contract test 后才可升级）
registry.enabled === false            →  DEPRECATED  （1 个：DB.SWIND）
```

> `docs/04` §8 的 `VERIFIED` 判定是 **7 项 AND 条件**（含「至少一次真实 Contract Test 通过」）。
> 我们的 `verified` 已满足「真机实测通过」，但仍需补 **contract test 记录**才能完全对齐文档定义
> —— 见 §16 未决事项 R1。

### 7.3 由 Registry 驱动的请求构造

```python
# 伪代码：Adapter 内部
def build_request(endpoint, canonical_data, instance):
    uri    = endpoint["uri"]
    method = endpoint["methods"][0]

    # 1) 产品差异（Civil Designer 扁平体 / NX Assign 包装）
    wrapper = endpoint["wrapper"]["write"]        # "Assign" | "Argument" | "none"
    body = canonical_data if wrapper == "none" else {wrapper: canonical_data}

    # 2) 求解器门控
    if endpoint.get("solver") and endpoint["solver"] != instance.solver:
        raise SolverUnsupported(endpoint["solver"], instance.solver)

    # 3) 破坏性护栏（NX 系 DELETE 必须带路径 key）
    if method == "DELETE":
        if endpoint.get("risk", {}).get("delete_without_body_is_global"):
            if not item_id:
                raise GlobalDeleteRejected("NX 系 DELETE 必须带路径 key")
            uri = f"{uri}/{item_id}"
        elif endpoint.get("risk", {}).get("delete_all_via_body") and payload.get("Type") == 0:
            raise GlobalDeleteRejected("Designer Type=0 = 删除全部")

    # 4) 请求体形态（数组 / 对象）
    if endpoint.get("schema_shape") == "flat_array" and not isinstance(body, list):
        raise SchemaValidationError("该端点要求数组体")
    return method, uri, body
```

## 8. 安全模型

### 8.1 身份与信任边界

| 项 | 规则 |
| --- | --- |
| **身份来源** | **必须由服务器生成**（`ExecutionContext` 由 Core 构造） |
| 客户端可提供 | `project_id`、`software_instance_id` |
| **客户端不可提供** | `user_id`、`tenant_id`、`roles`、`permissions`、`session_id` |
| 客户端提供的 `context.identity` | **必须被忽略/拒绝**，不得覆盖 |
| STDIO | 可用 local trusted identity（`AuthenticationMethod.LOCAL`） |
| HTTP | 必须鉴权（`AuthenticationMethod.TOKEN`） |

### 8.2 Effective Permission 链

```
User → Global Roles → Tenant Membership → Tenant Roles
     → Project Membership → Project Roles → Resource ACL → Explicit Deny
```

- **Explicit Deny 优先**
- **AI Agent 有效权限 = 用户有效权限 ∩ Agent 权限**（不得提权）
- `EffectivePermissionService.resolve(identity, resource) -> set[str]`

### 8.3 密码 / 会话 / Token

| 项 | 规则 |
| --- | --- |
| 密码哈希 | **Argon2id** |
| 登录失败 | 计数 + 账号锁定；**不泄露用户是否存在** |
| Session | 有 `expires_at`、可撤销、绑定 User + Tenant |
| **Token 存储** | **只存 hash**，绝不存明文 |
| Session 失效 | 过期 / 撤销 / 用户锁定 → 立即失效 |

### 8.4 Confirmation Token

必须：**server-generated / 短期 / 绑定 user / 绑定 tenant / 绑定 operation / 绑定 resource / 一次性**。
**禁止**用固定字符串（`CONFIRM` / `YES` / `true`）作为确认。
缺 Token → `STRUCTAI-4100`。

### 8.5 密钥

- `CredentialProvider` 接口：`get_secret` / `set_secret` / `delete_secret`
- Core Alpha 实现：`EnvironmentCredentialProvider`（读环境变量）
- `SoftwareInstanceModel.credential_reference` 只存**引用名**，不存值
- **绝不写入日志 / 审计 / 响应**

```

 2 Authenticate
 3 Build Server IdentityContext        ← 身份只能在此生成
 4 Build ExecutionContext
 5 Resolve Tool

 8 Schema Validation

10 Preconditions
11 Effective Permission
12 Quota / Rate Limit
13 Confirmation
14 Idempotency                         ← 先于 Lock
15 Concurrency / Resource Lock
16 Capability Check
17 Task / Transaction
18 Adapter
19 Result Normalization
20 Postconditions                      ← 先于 Release Lock
21 Release Lock
22 Persist Result
23 Audit
24 Trace
25 Event
26 MCP Response
```

**不可变依据**：

- **Resource Resolve 先于权限/锁**（跨租户拦截点必须最先）

- **Capability 先于 Task**（无能力的任务不得入队）

## 10. 任务引擎

### 10.1 状态机（12 态）

```
CREATED → VALIDATING → QUEUED → RUNNING → PROCESSING → COMPLETED
                          ↓        ↓          ↓
                        FAILED  TIMEOUT   CANCEL_REQUESTED → CANCELLED
                          ↓
                       RETRYING → QUEUED
                          ↓
                      RECOVERING
```

**状态机必须集中实现**（`task/state_machine.py`），不得散落。

### 10.2 关键机制

| 机制 | 规则 |
| --- | --- |
| **Lease** | `lease_owner` / `lease_until` / `last_heartbeat`；租约必须**原子更新** |
| **Heartbeat** | Worker 定期续租；过期则任务可被恢复 |
| **Recovery** | 查 `QUEUED/RUNNING/PROCESSING/RECOVERING` → 检查 lease → 有效则等待/对账，否则 `RECOVERING` → 重试/重排 |
| **恢复策略** | `REQUEUE` / `FAIL` / `RESUME`（按 Operation 的 `recovery_policy`） |
| **禁止** | **不得把恢复中的 Task 直接标记 `COMPLETED`** |
| **DAG** | `TaskStep.depends_on`；**循环依赖必须在提交前拒绝** |
| **优先级** | `CRITICAL` / `HIGH` / `NORMAL` / `LOW`；队列按 priority + created_at |
| **并发** | 四级（global / tenant / user / software-instance）取**最严格**；实例策略 `SERIAL`(默认) / `LIMITED` / `PARALLEL` |
| **Cancellation** | MCP Cancel → `TaskEngine.cancel()` → `CANCEL_REQUESTED` → `Adapter.cancel()` → `CANCELLED`；**不得杀 Python 进程，不得伪造 `CANCELLED`** |
| **Progress** | 唯一来源是 Task Engine；范围 0–100；**Progress 不可信**（来自 Adapter 的进度需校验） |

### 10.3 幂等原子性

```sql
-- 必须原子 INSERT，禁止 SELECT → INSERT
INSERT INTO idempotency_records (tenant_id, idempotency_key, request_hash, ...)
VALUES (...) ;   -- 唯一约束冲突 → 返回已有响应
```
唯一键：`(tenant_id, idempotency_key)`。
`request_hash` 不同 → `STRUCTAI-1300`（冲突）。

### 10.4 乐观并发

```sql
UPDATE <table> SET version = version + 1
WHERE id = :id AND version = :expected_version;
-- 影响 0 行 → STRUCTAI-1300 Concurrency Conflict
```

## 14. 架构红线（禁止项汇总）

### 14.1 依赖与分层

- 禁止 `Domain → MIDAS` / `Domain → SQLAlchemy` / `Domain → FastAPI` / `Domain → MCP SDK`
- 禁止 `Interface → SQLAlchemy` / `Interface → Adapter` / `Interface → Filesystem`
- 禁止 `Adapter → FastAPI`
- 禁止反向依赖（`Infrastructure → Interface` 等）

### 14.2 命名与内容

- 禁止 `midas_xxx()` / `midas_api()` / `midas_endpoint()` / `midas_node_create()` / `midas_analysis_static()`
- 禁止 `from midas import ...`
- **Core 中不允许出现 MIDAS endpoint / 参数 / 响应 / SDK**
- `grep -R "midas" app/` 预期 **0** 处业务依赖
- 厂商专属代码**每个厂商一个子包**（`adapters/midas/`、`adapters/etabs/`）；`app/` 的其余部分一律 0 处厂商字样（`grep -ri <厂商名> app/` 在各自子包**之外** = 0，见 §16 R92）
- Capability 中禁止出现 `MIDAS` / `CSI` / `ANSYS` 等厂商名

### 14.3 安全与数据

- 禁止客户端声明身份（`user_id` / `tenant_id` / `roles` / `permissions`）
- 禁止 AI Agent 提权
- 禁止用固定字符串作 Confirmation
- **绝不记录 secret**（password / API key / token / private key）
- 禁止依赖 UI 过滤做租户隔离
- 禁止从数据库执行任意 Python
- 禁止启动时静默 `ALTER TABLE`
- 禁止明文 API Key 入库

### 14.4 运行时

- 禁止把恢复中的 Task 直接标记 `COMPLETED`
- 禁止循环依赖的任务提交
- 禁止无限 payload（必须分页）
- Registry 校验失败 → **Server MUST NOT become READY**
- 单实例失败不得让整个服务器不可用
- 取消不得杀 Python 进程
- Repository 不得自行 `commit`
- `ExecutionService` 不得变成巨型类

### 14.5 扩展性

- 接入新软件只允许：新增 Adapter + Mapping + API Registry 数据
- **不得修改 9 Tool Contract**
- UI 不能反向定义 Core
